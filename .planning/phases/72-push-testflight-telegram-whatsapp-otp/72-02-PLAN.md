Общая схема обоих провайдеров (каждый провайдер реализует её сам, общий код только в otpErrors.ts):
1. sendVerificationRequest({ identifier: phone, token }, ctx). Вторым шагом const global = await rateLimiter.limit(ctx, "otpSendGlobal"); при !global.ok: logError("otpSendGlobal limit reached", new Error(`channel ${channel}`)) и throw ConvexError { code: "SERVICE_UNAVAILABLE", channel } (для пользователя это общая ошибка сервиса, для оператора — сигнал в Sentry/логах).
2. Проверка env. Если переменной нет: logError("<Provider>OTP config error", new Error("<ИМЯ_ПЕРЕМЕННОЙ> is not set")) и throw ConvexError { code: "SERVICE_UNAVAILABLE", channel }.
3. fetch оборачивается в tryCatch; сетевая ошибка → logError + ConvexError UNKNOWN.
4. Любая ошибка провайдера: logError("<Provider>OTP send error", new Error(<строка с кодом/текстом провайдера, HTTP-статусом и maskPhone(phone)>)). Никогда не включать token (код OTP) и полный номер. Наружу только ConvexError({ code, channel }) — без сырого текста.
