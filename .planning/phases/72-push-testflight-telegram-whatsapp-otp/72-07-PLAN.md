Правило коммитов для eas-cli (D-20, сверено по исходникам eas-cli 21.5.0, build/utils/repository.js и vcs/clients/git.js): все вопросы EAS про коммит («Commit changes to git?», «Can we commit these changes to git for you?») задаются только при cli.requireCommit: true в eas.json, а при ответе «да» EAS коммитит ВСЕ файлы (commitAllFiles, эквивалент git add -A), то есть и работу phone-review. Без requireCommit EAS не спрашивает и загружает рабочий каталог как есть (с учётом .gitignore / .easignore). Поэтому до сборок Claude проверяет: node -e "process.exit(require('./eas.json').cli?.requireCommit?1:0)" код 0 и переменная EAS_BUILD_AUTOCOMMIT не задана (test -z "$EAS_BUILD_AUTOCOMMIT"). Если EAS всё же задаст вопрос о коммите, отвечать «No» / «Abort build process» и разбираться, а не соглашаться. EAS_NO_VCS=1 не использовать: он не исключает незакоммиченные файлы из архива и только отключает git-логику. Claude фиксирует git log -1 --format=%H до сборок и сверяет после: хэш не должен измениться.
