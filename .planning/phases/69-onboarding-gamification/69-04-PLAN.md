<objective>
Реализовать серверную часть геймификации: идемпотентное начисление бейджей в момент завершения обработки блюда и три запроса/мутации для UI (непоказанный бейдж, отметка «показан», список выданных).

Purpose: обработка блюда в этом проекте двухэтапная и часто завершается в фоновом `internalAction` (Phase 7, MEAL-03/04) — пользователя может не быть на экране. Поэтому начисление обязано быть серверным и идемпотентным, а UI (план 69-05) обязан узнавать о бейдже реактивным запросом, а не из ответа мутации (69-RESEARCH.md Pitfall 3). Подсчёт стрика при этом нельзя взять из `getStreak`: эта query авторизуется через `getAuthUserId`, которого в серверном пайплайне нет — поэтому логика выносится в общую чистую функцию.
Output: `convex/utils/streakDays.ts` (+ рефактор `getStreak`), четыре файла в `convex/badges/`, две однострочные врезки в meal-пайплайн, verify-скрипт подсчёта стрика.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Клиент → `markBadgeSeen` | Клиент передаёт идентификатор документа бейджа |
| Meal-пайплайн (action) → `checkAndAwardBadges` | Серверный вызов с `userId`, полученным внутри доверенного пайплайна |
