<objective>
Исправить DST-баг недельной истории во всех четырёх запросах, которые рисуют недельную карусель главного экрана (FLOW-03, решение D-04).

Purpose: Сейчас клиент вызывает `new Date().getTimezoneOffset()` один раз и присылает одно число, а сервер применяет его ко всем семи дням недели. `getTimezoneOffset()` возвращает корректное смещение только для той даты, на которой вызван, поэтому в неделю с переходом на летнее/зимнее время часть дней смещается на час: запись, сделанная в воскресенье поздним вечером, уезжает в понедельник и вовсе выпадает из недельного окна. Роадмап называет только `getWeekMeals.ts`, но байт-в-байт тот же алгоритм скопирован ещё в трёх файлах, и все четыре рисуются на одном экране — по D-04 чинятся все четыре.
Output: Клиент считает границы недели по своему локальному календарю (8 отметок полуночи и 7 локальных дат), сервер их валидирует и раскладывает записи по этим границам; общая математика живёт в двух хелперах, а не в четырёх копиях; корректность доказывается скриптом на фиксированных таймстампах вокруг реального перехода DST.
</objective>

Создать клиентский хелпер `lib/utils/getLocalWeekBounds.ts`. Именованный экспорт типа `LocalWeekBounds` с полями `dayStartsUtc: number[]` (ровно 8 элементов) и `weekDates: string[]` (ровно 7 элементов). Default export `getLocalWeekBounds(now: Date = new Date()): LocalWeekBounds`.

Алгоритм: `daysFromMonday = (now.getDay() + 6) % 7`; для `i` от 0 до 7 включительно построить локальную дату конструктором `new Date(now.getFullYear(), now.getMonth(), now.getDate() - daysFromMonday + i)` и взять `.getTime()` — это и есть `dayStartsUtc[i]`, момент локальной полуночи в UTC-миллисекундах. Именно этот конструктор разрешает переход DST корректно: в неделе с переводом стрелок расстояние между соседними отметками становится 23 или 25 часов, а не всегда 24. Восьмая отметка — полночь следующего понедельника — нужна как правая граница недели. `weekDates[i]` для `i` от 0 до 6 формируется из той же локальной даты через `getFullYear()`, `getMonth() + 1`, `getDate()` с `String(...).padStart(2, "0")` — дословно как `toLocalDateString` в `lib/health/healthKit.ts`. `toISOString()` для формирования дат НЕ использовать ни при каких условиях: он переводит момент в UTC и для клиентов восточнее Гринвича даёт предыдущие сутки. Никаких зависимостей, включая `date-fns`, в файл не добавлять.

Создать серверный хелпер `convex/utils/localWeekBounds.ts` с русским doc-комментарием в стиле соседнего `localDayBoundaries.ts` (зачем существует, что покрывает, что нет). Файл — чистые функции без импортов из `_generated/server` и без `convex/values`: он должен импортироваться и из Convex-запросов, и из ad-hoc скрипта под `ts-node`. Три именованных экспорта (группировка нескольких именованных экспортов в одном файле оправдана тем, что все три работают с одним значением — границами недели; прецедент такой группировки в кодовой базе — файлы `convex/tables/*.ts`):

`assertLocalWeekBounds(dayStartsUtc: number[]): void` — бросает `new Error("Invalid week bounds")`, если: длина массива не равна 8; хотя бы один элемент не является конечным целым числом; последовательность не строго возрастающая; шаг между соседними отметками выходит за пределы 22–26 часов; полный размах `dayStartsUtc[7] - dayStartsUtc[0]` выходит за пределы «7 суток плюс-минус 2 часа». Последние две проверки — не косметика: границы окна теперь приходят от клиента, и без них клиент может запросить произвольно широкий диапазон и заставить сервер собрать всю историю пользователя целиком.

`getLocalWeekDayIndex(dayStartsUtc: number[], timestampUtc: number): number` — возвращает индекс `i` из диапазона 0..6, для которого выполняется `dayStartsUtc[i] <= timestampUtc < dayStartsUtc[i + 1]`, и `-1`, если момент не попадает в неделю. Никакой арифметики со смещениями внутри: только сравнение с готовыми границами.

`assertLocalWeekDates(weekDates: string[]): void` — бросает `new Error("Invalid week dates")`, если: длина не равна 7; хотя бы одна строка не соответствует шаблону из четырёх цифр, дефиса, двух цифр, дефиса, двух цифр; строки не строго возрастают лексикографически; расстояние между первой и последней датой не равно ровно шести суткам. Разбирать даты через `Date.UTC` по компонентам строки — в UTC перехода DST нет, арифметика безопасна.

Создать `scripts/verifyWeekBucketing.ts` — ad-hoc проверка без тестового фреймворка, утверждения через `node:assert/strict`, при провале процесс завершается ненулевым кодом, при успехе печатается строка `verifyWeekBucketing: OK`. Скрипт импортирует `getLocalWeekBounds` из `@/lib/utils/getLocalWeekBounds` и все три функции из `@/convex/utils/localWeekBounds`. Фиксированная неделя — 19–25 октября 2026 в зоне `Europe/Berlin` (в ночь на воскресенье 25 октября 2026 в ЕС переводят стрелки назад, CEST переходит в CET).
