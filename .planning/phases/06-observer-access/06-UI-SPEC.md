# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Note

Проект — Expo/React Native (TerenAI), не web. Дизайн-система полностью кастомная (`components/ui/*`, `components/settings/*`, `components/home/*`), shadcn/Tailwind/registry-концепции из общего шаблона неприменимы напрямую — соответствующие секции ниже заполнены как "not applicable", а не пропущены.

Этот контракт покрывает **только новый UI фазы 6**:

| Экран/компонент | Маршрут / файл | Требование |
|---|---|---|
| «Мой код» (сторона пациента: код, «поделиться», регенерация, список привязанных наблюдателей, отзыв) | `app/app/(settings)/observerCode.tsx`, новый пункт в `app/app/(tabs)/settings.tsx` | OBSV-01, OBSV-02, OBSV-07 |
| «Кого я наблюдаю» (сторона наблюдателя: список карточек, ввод кода) | `app/app/(settings)/observedList.tsx`, `onPress` на существующей кнопке-стрик `components/home/HomeHeader.tsx:25-34` | OBSV-01, OBSV-03, OBSV-04, OBSV-05, OBSV-07 |
| `ObservedPatientCard` | `components/observer/ObservedPatientCard.tsx` | OBSV-04, OBSV-05 |
| `ObserverListItem` | `components/observer/ObserverListItem.tsx` | OBSV-02, OBSV-07 |
| Детальный вид пациента (только чтение) | `app/app/(settings)/observedPatient/[patientId].tsx` (или аналог) — переиспользует `HomeMacroSummary`, `HomeGlucoseSummary`, `HomeBloodPressureSummary`, `HomeMovementSummary` с внешними (observer-scoped) данными вместо `useQuery` собственных | OBSV-06 |

Типографика/цвет/spacing ниже — контракт **для нового UI** этого списка. Переиспользуемые как есть компоненты (`SettingsItem`, `SettingsGroup`, `OTPInput`, `AlertDialog`, `ScreenHeader`, `Card`, `Button`, `Toast`) сохраняют свою уже установленную визуальную форму без изменений — эта фаза их не редизайнит, только компонует.

**Ключевое UX-ограничение (из CONTEXT.md, Deferred Ideas):** доступ наблюдателя — строго read-only и строго «сегодня». Детальный вид пациента (OBSV-06) должен визуально совпадать с главным экраном владельца, но без точек входа в мутации/полную историю: скрыть/отключить в переиспользуемых Home-компонентах любые ссылки на добавление записи (фото блюда, ручной ввод глюкозы/давления) и переходы в полные логи (`glucoseLog`, `bloodPressureLog`, `movementLog`, `nutrients` — кнопки «Все»/переход по тапу на карточку в этих компонентах). Это архитектурное ограничение обязано быть видимым в самом UI, а не только в правах Convex-функций.

## Spacing Scale

Declared values (проектная реализация — база 4px, не строго 8pt, но кратно 4):

| Token | Value | Usage в этой фазе |
|-------|-------|-------|
| xs | 4px | Gap между иконкой и текстом в бейдже предупреждения |
| sm | 8px | Внутренний padding бейджа, gap между метриками в карточке |
| md | 16px | Стандартный внутренний padding карточек (`Card` default), gap между секциями списка |
| lg | 24px | Отступ между блоком кода и списком «Мои наблюдатели» на экране настроек |
| 2xl | 48px | Вертикальный отступ пустого состояния (иконка/текст по центру) |

Exceptions (переиспользование существующих, не новых, размеров — не изобретать заново):
- Строка `SettingsItem`: высота 52px (фиксирована в существующем компоненте, используется для строки «Мой код» в настройках и для строк списка наблюдателей, если они компонуются как `SettingsItem`)
- Блок кода на экране «Мой код»: высота 100px, `padding: 12/16`, `gap: 16` между цифро-боксами — визуально повторяет статический вариант `OTPInputBox` (не редактируемый, без caret), не новое значение
- Круглая иконка-контейнер (32px) внутри строк списка — повтор паттерна `HomeGlucoseSummary`/`SettingsItem` rowIcon
- Минимальный тач-таргет для любой новой иконки-кнопки без текста (например, кнопка «Отозвать» рядом со строкой наблюдателя) — 44×44px, даже если визуальная иконка меньше (18–20px), с прозрачным hit-slop

## Typography

Применяется к **новому** UI фазы 6 (карточки наблюдаемых, экран «Мой код», список «Кого я наблюдаю», бейджи предупреждений). Переиспользуемые компоненты (`SettingsItem` — 16/500, `ScreenHeaderTitle` — 18/600, `OTPInput` цифры — 32/600, `ScreenMainTitle` — 22/600) сохраняют собственную типографику без изменений.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Label | 12 | 400 | 1.4 | Подписи метрик на карточке («глюкоза», «приёмов пищи», «шаги»), контекст измерения, дата подключения наблюдателя, текст бейджа предупреждения |
| Body | 16 | 400 | 1.5 | Значения метрик, имя/email наблюдателя в списке, тело пустых состояний |
| Heading | 20 | 600 | 1.2 | Заголовки секций («Поделитесь кодом», «Мои наблюдатели»), имя наблюдаемого пациента на карточке и в шапке детального экрана |
| Display | 28 | 600 | 1.2 | Крупное число кода на экране «Мой код» (с `letterSpacing`, аналогично цифрам `OTPInput`, но статично) |

Weights used: **400 (regular), 600 (semibold)** — ровно 2, как того требует контракт. Никаких новых начертаний (300/500/700) для нового UI фазы не вводить.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `getColor("background")` #f9fafb | Фон экранов `observerCode.tsx`, `observedList.tsx`, детального вида — тот же фон, что и у остальных экранов настроек (`health.tsx`) |
| Secondary (30%) | `getColor("base")` #ffffff (карточки) + `getColor("muted")` #f3f4f6 (круглые иконки-контейнеры, неактивные состояния) | Поверхность `ObservedPatientCard`, блок кода, `SettingsGroup`-карточка списка наблюдателей |
| Accent (10%) | `getColor("amber")` #f59e0b — превышение калорий; `getColor("red")` #ef4444 — глюкоза вне диапазона | **Только** бейдж предупреждения на `ObservedPatientCard` (фон, иконка `AlertTriangleIcon`/`TriangleAlertIcon`, текст) — фон бейджа рендерить как `getColor("amber", 0.12)` / `getColor("red", 0.12)`, сам текст/иконка — непрозрачным цветом. Больше нигде в новом UI этой фазы accent-цвета не использовать (кнопки, ссылки, заголовки остаются в нейтральной палитре `foreground`/`mutedForeground`, как и во всём остальном приложении — здесь нет "бренд-акцента", primary-кнопки уже используют `foreground`, не цвет) |
| Destructive | `getColor("red")` #ef4444 (он же `getColor("destructive")`) | Действия «Отозвать доступ» (пациент → наблюдатель) и «Убрать из списка наблюдаемых» (наблюдатель → пациент) — оба через существующий `AlertDialog` с `destructive` |

Accent reserved for: **только** бейджи предупреждений на карточке наблюдаемого (превышение калорий / глюкоза вне диапазона, D-05/D-06/D-07 из CONTEXT.md). Не использовать accent-цвета для CTA-кнопок, ссылок или декоративных элементов — это разошлось бы с существующей палитрой приложения, где цвет зарезервирован под данные (БЖУ, глюкоза, стрик), а не под chrome.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA — «Мой код» (пациент делится кодом) | «Поделиться кодом» — открывает нативный `Share.share()` (RN, без новой зависимости) с текстом вида `Мой код в TerenAI: {code}`. Вторичное действие рядом: «Обновить код» (variant="secondary" или "outline", не primary) |
| Primary CTA — «Кого я наблюдаю» (наблюдатель добавляет пациента) | «Ввести код» — открывает `OTPInput` (length=6) в `BottomSheet` или инлайн-карточке; автосабмит по заполнении 6 цифр (как в остальных OTP-флоу приложения) |
| Empty state — «Кого я наблюдаю» (0 подключённых пациентов) | Заголовок: «Вы пока никого не наблюдаете». Тело: «Введите код, которым поделился пациент, чтобы увидеть его данные за сегодня.» + кнопка «Ввести код» |
| Empty state — «Мои наблюдатели» (инлайн-блок под кодом на экране пациента, 0 привязанных наблюдателей) | «Пока никто не подключился по вашему коду. Поделитесь кодом, чтобы дать доступ.» (без отдельного заголовка — компактная строка под блоком кода) |
| Error — код не найден (`redeemCode` throws "Code not found") | Тряска `OTPInput` (`ref.flashError()`, уже реализовано в компоненте) + toast: «Код не найден. Проверьте и попробуйте снова.» |
| Error — попытка ввести собственный код (`observerId === patientId`) | Toast: «Это ваш код — наблюдать за собой нельзя.» |
| Error — общая ошибка мутации (сеть/сервер) | Toast (`variant: "error"`): «Не удалось подключиться. Попробуйте ещё раз.» — тон соответствует существующему `health.tsx` («Не удалось получить доступ к Apple Health.») |
| Destructive confirmation — отзыв доступа наблюдателю (сторона пациента, OBSV-07) | `AlertDialog title`: «Отозвать доступ». `description`: «Наблюдатель больше не будет видеть ваши данные. Чтобы вернуть доступ, поделитесь кодом снова.» (кнопки берутся из `AlertDialog` как есть: «Отмена» / «Подтвердить», подписи не кастомизируются — компонент их не параметризует) |
| Destructive confirmation — убрать пациента из списка (сторона наблюдателя, OBSV-07) | `title`: «Убрать из списка наблюдаемых». `description`: «Вы перестанете видеть данные этого пациента. Чтобы возобновить доступ, потребуется новый код.» |
| Confirmation — обновление кода (регенерация, не деструктивно к связям, но инвалидирует старый код) | `title`: «Обновить код доступа». `description`: «Прежний код перестанет работать. Уже подключённые наблюдатели доступ не потеряют.» `destructive={false}` — это не удаляет данные, только меняет значение кода |
| Бейдж — превышены калории | «Превышены калории» (Label 12/400, иконка `TriangleAlertIcon` 14px, цвет `amber`) |
| Бейдж — глюкоза вне диапазона | «Глюкоза вне нормы» (Label 12/400, иконка `TriangleAlertIcon` 14px, цвет `red`) |
| Идентификация наблюдателя/пациента в списках (нет отдельного поля "имя связи") | Приоритет отображения: `name` → `email` → `phone` → «Гость» (для анонимных пользователей — терминология из Phase 3, «Продолжить без аккаунта») |
