В `convex/rateLimit.ts` в объект конфигурации `RateLimiter` добавить второй ключ `observerCodeRedeem` рядом с существующим `aiFeatures`: `{ kind: "fixed window", rate: 10, period: HOUR }`. `HOUR` уже импортируется в этом файле, новых импортов не нужно. Существующий `aiFeatures` и экспорт `getAiFeaturesRateLimit`/`getServerTime` не трогать — они обслуживают AI-лимит и не связаны с этой фазой.

Обоснование лимита: код постоянный, шестизначный и не истекает (D-02). Пространство — 1 000 000 значений. Без ограничения частоты скрипт подбирает его и получает доступ к медицинским данным чужого человека. 10 попыток в час на вызывающего делает перебор непрактичным, не мешая живому человеку, который ошибся при вводе. Это единственная поверхность в фазе, где неограниченные попытки конвертируются в доступ.

Создать `convex/observers/redeemCode.ts` — мутация с аргументом `code: v.string()`. Порядок шагов строго такой:

1. `observerId` через `getAuthUserId(ctx)`; при `null` — `"Unauthorized"`.
2. Валидация формы кода до любого обращения к базе: строка должна состоять ровно из 6 цифр (проверка регулярным выражением на 6 символов из диапазона цифр). При несовпадении бросить `new Error("Code not found")` — та же ошибка, что при отсутствии кода, чтобы ответ не позволял отличить «неверный формат» от «нет такого кода». Это отсекает мусорный ввод до запроса к индексу.
3. Применить лимит: `rateLimiter.limit(ctx, "observerCodeRedeem", { key: observerId, throws: true })` с импортом `rateLimiter` из `../rateLimit`. Ключ — именно `observerId`, а не строка кода: иначе атакующий обходит лимит, меняя перебираемое значение. Лимит применяется ДО поиска профиля.
4. Найти профиль владельца кода через `ctx.db.query("profiles").withIndex("byObserverCode", (q) => q.eq("observerCode", code)).first()`; при отсутствии — `new Error("Code not found")`.
5. Взять `patientId = patientProfile.userId`. Если `patientId === observerId` — бросить `new Error("Cannot observe yourself")`. Отдельная ошибка нужна, потому что UI показывает для неё собственный текст.
6. Проверить существующую связь через индекс `byObserverAndPatient` с `q.eq("observerId", observerId).eq("patientId", patientId)` и `.first()`. Если связь есть — вернуть её `_id` без вставки. Идемпотентность обязательна: повторный ввод того же кода не должен плодить дубликаты строк, иначе список наблюдаемых покажет одного пациента дважды, а отзыв удалит только одну из связей.
7. Вставить строку `observerLinks` с `{ observerId, patientId }` и вернуть её id.

Строки исключений `"Code not found"` и `"Cannot observe yourself"` — часть контракта с UI (план 06 сопоставляет их с разными тостами). Не переформулировать и не переводить на русский: пользовательские тексты формирует клиент.
