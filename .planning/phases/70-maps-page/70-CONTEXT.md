# Phase 70: maps-page - Context

**Gathered:** 2026-10-07
**Status:** Ready for planning

<domain>
## Phase Boundary

Вкладка «Карты» (сейчас статичная заглушка `app/app/(tabs)/maps.tsx`) становится единым центром наблюдения: сверху блок «Поделитесь кодом», под ним ввод кода для наблюдения, затем два таба «Наблюдаемые / Наблюдатели» с карточками. Функциональность наблюдения (коды, связи, права, детальный вид наблюдаемого) уже построена в Phase 6 и не меняется — фаза про новую страницу-контейнер и перенос точек входа. Из Профиля и шапки Главной убираются кнопки, ведущие к старым экранам наблюдения.

</domain>

<decisions>
## Implementation Decisions

### Раскладка страницы (из запроса пользователя)
- **D-01:** Порядок сверху вниз: (1) «Поделитесь кодом» — код компактно, без полей ввода, рядом две иконки-кнопки: «обновить» и «отправить»; (2) ввод кода наблюдателя; (3) переключатель из 2 табов «Наблюдаемые / Наблюдатели»; (4) карточки выбранного таба.
- **D-02:** Из Профиля убирается пункт «Доступ наблюдателя», из шапки Главной — кнопка «Кого я наблюдаю» (иконка UsersIcon). Кнопка серии (streak) в шапке остаётся.

### Ввод кода наблюдателя
- **D-03:** 5 ячеек OTP всегда видны на странице (без кнопки «Ввести код»), без фонового блока вокруг (как уже решено для экрана «Кого я наблюдаю»); тёмная тема — усиленные границы ячеек (`OTPInput`, правка из Phase 07.1 корректировок).
- **D-04:** После успешного ввода: поле очищается, активный таб переключается на «Наблюдаемые», появляется новая карточка. Отдельный toast об успехе не показывается — карточка и есть подтверждение.
- **D-05:** Ошибки как сейчас: вспышка красной границы ячеек (`flashError`) + toast; три существующих текста — «Код не найден…», «Это ваш код — наблюдать за собой нельзя.», «Не удалось подключиться…». Поле очищается для повторного ввода.

### Карточка наблюдаемого (таб «Наблюдаемые»)
- **D-06:** Компактные блоки в ряд: «Калории / Активность / Приём пищи», всегда все три. Если данных нет — значение «—» (сетка не «прыгает» между карточками).
- **D-07:** Блок «Активность» — иконка кроссовки (`SportShoeIcon`) + число шагов + подпись «шаги», в стиле двух других плиток (иконка / число / подпись), без полоски прогресса и без км. Данные берутся из `movementData` наблюдаемого (есть только при iOS/HealthKit); `null` → «—».
- **D-08:** Для пациентов на glucometer-треке добавляется четвёртая компактная плитка «Глюкоза» (последнее значение + единица/контекст, как сейчас). Бейджи «Превышены калории» / «Глюкоза вне нормы» (Phase 6) сохраняются под плитками.
- **D-09:** Стиль карточки и плиток — как у `ObservedPatientCard` после корректировки Phase 07.1 (фон `#0A0D12`, плитки `#15181F` со свечением через `getNutrientGlow`, аватар с инициалом, кнопка удаления с подтверждением). Клик по карточке открывает существующий детальный экран `observedPatient/[patientId]`.

### Claude's Discretion
- Таб «Наблюдатели»: пользователь не обсуждал содержимое карточек. Решение по умолчанию — карточка в том же визуальном стиле: аватар с инициалом, имя, дата подключения («Подключён {дата}»), кнопка «Отозвать доступ» с подтверждением (поведение `ObserverListItem`/`revokeLink` из Phase 6, D-08). Данных наблюдателя (калории/активность) нет и быть не должно.
- Поведение кнопки «обновить»: подтверждение через `AlertDialog` (как в `observerCode.tsx`: прежний код перестанет работать, подключённые наблюдатели доступ не теряют). Кнопка «отправить» — системный `Share` с текстом «Мой код в TerenAI: {код}».
- Судьба старых роутов `(settings)/observerCode` и `(settings)/observedList`: удалить после переноса логики на «Карты» (на них больше нет точек входа); `observedPatient/[patientId]` остаётся. Начальный выбор таба: «Наблюдаемые». Пустые состояния табов — текст + подсказка («Введите код выше…» / «Поделитесь кодом…»), в стиле `HomeEmptyState`.
- Точная визуальная реализация переключателя табов — на `SegmentedControl` (существующий компонент) либо аналог, на усмотрение планировщика.

</decisions>
