  <what-built>
The full two-stage meal analysis flow: taking a photo (or entering a text description) now lands on a new "Проверьте блюдо" confirmation screen showing the AI-detected ingredient list within seconds — before any database candidate search runs. The list is editable inline (name, ±10g stepper with tap-to-enter-exact-value, add, remove/swipe-to-remove). Tapping "Подтвердить" creates the meal record and immediately hands off to background processing on the server (Convex scheduler) — the app does not block waiting for candidate search/translation/health-score/totals. When that background step finishes, an in-app toast confirms completion and the home screen's calorie/macro totals update automatically (Convex reactivity, no manual refresh). If the background step fails, the meal shows a dedicated error state with a "Повторить" button that re-runs only the failed step (not the whole AI analysis, and without spending an AI-limit unit) — with its own separate, tighter rate limit to prevent abuse. Leaving the confirmation screen without confirming triggers a "Уйти без подтверждения?" dialog.
  </what-built>

  <how-to-verify>
1. Run `npm run ios` (or `npm run android`) against a dev Convex deployment with `OPENROUTER_API_KEY`/`GOOGLE_GENERATIVE_AI_API_KEY` configured.
2. From the home screen, tap the camera action and take a photo of any food (or use "Описать блюдо" and type a description). Confirm: you land on "Проверьте блюдо" within a few seconds, with a skeleton placeholder briefly visible before the real ingredient list appears. For the photo path, the photo preview appears above the list; for the text path, no photo placeholder is shown.
3. Edit at least one ingredient's name (inline, no navigation), tap its grams value to open the number-pad keyboard and enter an exact value, use the ± stepper on another ingredient, swipe one ingredient away, tap "✕" on another, and tap "Добавить ингредиент" to add a new blank row (give it a name before confirming — an unnamed row should NOT block the confirm button, it is silently dropped).
4. Before tapping "Подтвердить", swipe back / tap the header back button — confirm the "Уйти без подтверждения?" dialog appears with "Остаться"/"Уйти" options; tap "Остаться" and confirm you're still on the confirmation screen.
5. Tap "Подтвердить". Confirm: the button shows "Подтверждаем…" briefly, then you land on the meal detail screen showing a loading skeleton (not the confirmation screen again).
6. Confirm the meal detail screen resolves to the finished result (name, macros, ingredient list) within a reasonable time, and that an in-app toast reading "Блюдо распознано и записано" appears once processing finishes.
7. Navigate to the home screen (tab or "Готово") and confirm the day's calorie/macro totals already reflect the new meal without a manual pull-to-refresh.
8. Optional but recommended if reproducible: force a background-stage failure (e.g., temporarily use an ingredient name unlikely to match any food candidate, or induce a network error) and confirm the meal shows the red-icon error state with "Не удалось распознать блюдо" / "Что-то пошло не так при обработке. Попробуйте ещё раз." and a working "Повторить" button that re-attempts processing.
9. Confirm the barcode-scan flow (unaffected by this phase) still works unchanged: scan a barcode, land directly on the meal detail screen without passing through the new confirmation screen.
  </how-to-verify>
