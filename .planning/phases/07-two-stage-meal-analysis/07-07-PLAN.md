<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → Convex public `query`/`mutation`/`action` | Untrusted caller; auth enforced via `getAuthUserId` |
| Convex scheduler → `internalAction`/`internalQuery` | Server-internal, not reachable from any client; carries no user identity by design |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Elevation of Privilege | `convex/foods/getFoodByIdentityInternal.ts` (auth check removed) | accept | `internalQuery` is not exposed on the public `api` object and cannot be invoked by any client — Convex only permits internal functions to be called from other server-side functions. The removed `getAuthUserId` guard is not reachable-from-client surface. |
| T-07-02 | Information Disclosure | `foods` table read without a user check | accept | `foods` rows are shared, non-user-scoped reference data (FDC/OFF nutrition identities, names, macros). They contain no PII and no per-user ownership column, so there is nothing to leak across users. Contrast with `meals`, which is user-owned and correctly keeps an explicit `userId` check in `updateMealInternal`/`replaceMealItemsInternal`. |
| T-07-03 | Spoofing | Existing authenticated callers of the public query (`meal.tsx`, `analyzeMealBarcode.ts`) | mitigate | Task 1 explicitly forbids modifying `convex/foods/getFoodByIdentity.ts` and asserts via `git diff --stat` that it and `analyzeMealBarcode.ts` are unmodified, so the client-facing auth boundary is preserved rather than downgraded. |
| T-07-SC | Tampering | npm/pip/cargo installs | n/a | This plan installs no packages — no new dependencies are added. |
</threat_model>
