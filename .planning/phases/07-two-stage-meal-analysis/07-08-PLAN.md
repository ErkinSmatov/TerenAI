<objective>
Fix the second bug found by the plan 07-06 human verification: detected ingredient names render in English on the new confirm-meal screen. The confirm screen (plan 07-04) is the first surface that shows raw AI-detected item names directly to the user, so the pipeline's long-standing English naming became user-visible for the first time.

Purpose: MEAL-01/MEAL-02 require the user to read and edit the detected ingredient list. A Russian-language app showing "grilled chicken breast, white rice (cooked), olive oil" fails that requirement in practice.
Output: The model emits an English search name AND a Russian display name per item; the UI shows Russian; the FDC vector search keeps using English.

## Why this is not a one-line `.describe()` change

The gap-closure brief proposed simply adding a Russian constraint to `items[].name`'s zod `.describe(...)`. Reading the code shows that would silently degrade nutrition accuracy for every meal:

1. `analyzeMealConfig.ts`'s `detect` prompt does not merely omit a language rule — it explicitly commands the opposite: `name: concise, generic English name (no brands)`. A zod `.describe()` saying "Russian" would directly contradict the system prompt.
2. `item.name` is not a display label. It is the **vector-search query text** and the **pipeline join key**: `searchFdcCandidates.ts` feeds it to `embedMany`, keys `candidatesByItem` by it, and `selectCandidates.ts::ensureSelections` re-joins on it (`inputName.toLowerCase()`).
3. The FDC corpus is embedded from **English only** — `convex/utils/backfillFoodEmbeddings.ts::buildEmbeddingText` builds each document vector from `food.name.en` plus `Category: {category.en}`. Making every query Russian turns every lookup into cross-lingual retrieval against an English index, degrading candidate quality for the app's core value proposition (достоверные калории).

So this plan keeps `name` English for retrieval and adds `nameRu` for display. Un-edited items therefore retain exactly today's match quality, while user-edited items behave exactly as they already do today (a user typing Russian into the name field already sends Russian into the search — that path is unchanged).
</objective>
