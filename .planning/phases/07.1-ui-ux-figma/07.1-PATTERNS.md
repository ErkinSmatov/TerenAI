### `lib/ui/getColor.ts` (utility, transform) — dual-theme resolver

**Analog:** itself, current implementation at `/Users/smatov/GitLab/CalYo/lib/ui/getColor.ts`

**Current flat pattern (lines 1-52):**
```typescript
const colors = {
  base: [255, 255, 255], // #ffffff
  primary: [59, 130, 246], // #3B82F6
  background: [249, 250, 251], // #f9fafb
  foreground: [3, 7, 18], // #030712
  muted: [243, 244, 246], // #f3f4f6
  ...
} as const;

type ColorName = keyof typeof colors;

export default function getColor(name: ColorName, opacity?: number) {
  "worklet";
  const color = colors[name];
  if (opacity !== undefined) {
    return `rgba(${color.join(", ")}, ${opacity})`;
  }
  return `rgb(${color.join(", ")})`;
}
```

**Required restructuring (per UI-SPEC "Theme Tokens" table):** keep the exact same call signature `getColor(name, opacity?)` so all ~40 call sites across `components/ui/*`, `components/home/*`, `components/nutrients/*`, `components/observer/*`, `components/settings/*` do NOT need per-callsite edits — only the internal color table needs to become theme-aware, e.g.:

```typescript
const palettes = {
  light: { base: [255,255,255], background:[249,250,251], foreground:[3,7,18], muted:[243,244,246], mutedForeground:[107,114,128], secondary:[229,231,235], primary:[59,130,246], destructive:[239,68,68], health:[34,197,94], ... },
  dark:  { base: [39,44,53] /* #272C35 surface-accent */, background:[10,13,18] /* #0A0D12 */, foreground:[243,245,249] /* #F3F5F9 */, muted:[21,24,31] /* #15181F */, mutedForeground:[146,153,165] /* #9299A5 */, secondary:[255,255,255] /* used w/ low opacity for rgba(255,255,255,0.08) border */, primary:[201,241,76] /* #C9F14C lime accent */, destructive:[233,69,69], health:[134,151,129], ... },
} as const;

// "worklet" note: getColor is called from Skia/Reanimated worklets (see CircularProgress.tsx,
// Nutrients.tsx animatedStyle). The active-theme read must remain worklet-safe — a shared value
// (react-native-reanimated) read synchronously, NOT a React Context hook, since Context cannot be
// read inside a "worklet" function. Mirror the SharedValue pattern already used in
// `components/ui/Button.tsx` (useSharedValue) and `components/ui/CircularProgress.tsx` (SharedValue prop).
```

**Auth/Context pattern to copy for the theme provider** (`context/AuthContext.tsx` lines 1-40, full file):
```typescript
import type { ReactNode } from "react";
import { createContext, useContext } from "react";

type AuthContextValue = { isAuthenticated: boolean; isLoading: boolean; signIn: ...; signOut: ...; };

const AuthContext = createContext<AuthContextValue | undefined>(undefined);

export function AuthContextProvider({ children }: Props) {
  const { isLoading, isAuthenticated } = useConvexAuth();
  const { signIn, signOut } = useAuthActions();
  const value: AuthContextValue = { isAuthenticated, isLoading, signIn, signOut };
  return <AuthContext.Provider value={value}>{children}</AuthContext.Provider>;
}

export function useAuthContext() {
  const context = useContext(AuthContext);
  if (context === undefined) {
    throw new Error("useAuthContext must be used within an AuthContextProvider");
  }
  return context;
}
```
Copy this exact shape for `ThemeContext.tsx` (`ThemeContextProvider` + `useThemeContext`), but back the "active theme" value with a Reanimated `SharedValue<"light"|"dark">` (not plain React state) so `getColor`'s worklet path can read it without a Context lookup — expose both the React-state boolean (for UI toggle rendering, e.g. Settings switch) and the shared value (for `getColor`/Skia consumers). Persist the choice (AsyncStorage or the existing Convex profile document, per CONTEXT.md D — "решается планировщиком/исполнителем").

### `lib/ui/resolveFontFamily.ts` (utility, transform) — Inter → Manrope/Outfit

**Analog:** itself, full file at `/Users/smatov/GitLab/CalYo/lib/ui/resolveFontFamily.ts` (56 lines)

**Current pattern (lines 3-26, weight table) and (lines 51-55, resolver):**
```typescript
const interFamilies = {
  normal: { 400: "Inter_400Regular", 600: "Inter_600SemiBold", ... },
  italic: { 400: "Inter_400Regular_Italic", ... },
} as const;

export default function resolveFontFamily({ weight, style }: Params) {
  const normalizedWeight = normalizeWeight(weight);
  const styleKey = style === "italic" ? "italic" : "normal";
  return interFamilies[styleKey][normalizedWeight];
}
```

**Required change:** per UI-SPEC only two weights are declared (400 Regular, 600 SemiBold) across two families (Manrope for text, Outfit for numeric/metric display values). This resolver has no concept of "family" today — it only takes weight+style. Per UI-SPEC section "Typography," numeric values (calorie totals, macro grams, glucose readings, steps) must render in Outfit while everything else uses Manrope. The signature must gain a `family` param (default `"manrope"`, opt into `"outfit"`), e.g.:
```typescript
type Params = { weight?: TextStyle["fontWeight"]; style?: TextStyle["fontStyle"]; family?: "manrope" | "outfit" };
const manropeFamilies = { normal: { 400: "Manrope_400Regular", 600: "Manrope_600SemiBold" }, italic: {...} };
const outfitFamilies = { normal: { 400: "Outfit_400Regular", 600: "Outfit_600SemiBold" }, italic: {...} };
```
Then `components/ui/Text.tsx` needs a new `family` prop (default `"manrope"`) threaded through to `resolveFontFamily`, used by any screen printing a numeric metric (dashboard calorie ring, glucose readings, macro grams).
