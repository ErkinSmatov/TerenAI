# Phase 07.1 Plan 01: Основа тёмной темы (палитры, getColor, провайдер, переключатель) Summary

**Тема-осведомлённый `getColor` с обратной совместимостью для ~295 вызовов, персистентный `ThemeContext` на MMKV и переключатель «Тёмная тема» в Настройках**

## Performance

- **Duration:** ~25 min
- **Completed:** 2026-09-17
- **Tasks:** 2
- **Files modified:** 7 (4 created, 3 modified)

## Accomplishments
- Обе палитры (`light`/`dark`) объявлены с идентичным набором из 35 ключей; светлые значения скопированы дословно, тёмные — по таблице UI-SPEC §Theme Tokens
- `getColor` переписан на тема-осведомлённый резолвер без изменения сигнатуры вызова — существующие 295 вызовов компилируются и работают без правок
- `useThemedStyles` даёт экранам путь к живому пересбору `StyleSheet` при смене темы, с кэшем по фабрике и теме
- `ThemeContext` персистирует выбор в MMKV через уже существующий `getColor.setActiveTheme`, статус-бар и переключатель в Настройках реагируют на тему

## Files Created/Modified
- `lib/ui/palettes.ts` - light/dark таблицы цветов, `ThemeName`/`ColorName`, типовая проверка совпадения ключей
- `lib/ui/getColor.ts` - тема-осведомлённый резолвер, `setActiveTheme`/`getActiveTheme`, `THEME_STORAGE_KEY`, синхронное чтение MMKV при инициализации модуля
- `lib/ui/useThemedStyles.ts` - хук пересборки `StyleSheet` по теме с кэшем
- `context/ThemeContext.tsx` - `ThemeContextProvider`/`useThemeContext` по образцу `AuthContext.tsx`
- `components/ThemedStatusBar.tsx` - `StatusBar`, следующий за активной темой
- `components/RootLayoutProvider.tsx` - `ThemeContextProvider` поднят на верх дерева провайдеров, `<StatusBar style="dark" />` заменён на `<ThemedStatusBar />`
- `app/app/(tabs)/settings.tsx` - переключатель «Тёмная тема» (`SettingsToggleItem` + `MoonIcon`) в группе настроек приложения

## Decisions Made
- Синхронное чтение MMKV на уровне модуля `getColor.ts` вместо Reanimated `SharedValue` — соответствует явному интерфейсному контракту PLAN.md; worklet-потребители получают тему через явный третий аргумент вместо чтения общего изменяемого состояния
- `ThemeContextProvider` размещён максимально высоко в дереве провайдеров (внутри `GestureHandlerRootView`, выше `ConvexAuthProvider`) — тема доступна любому экрану, включая гейтнутые auth-ом
- Переключатель темы добавлен в уже существующую группу настроек приложения (рядом с «Обновить вес», «Здоровье» и т.д.), без создания новой `SettingsGroup`, перед пунктом «Экспорт анализа»

## Deviations from Plan

None - plan executed exactly as written. Реализация обеих задач велась параллельно на диске (файлы Task 2 создавались до финальной проверки Task 1), поскольку `lib/ui/useThemedStyles.ts` (файл Task 1) импортирует `context/ThemeContext.tsx` (файл Task 2) — это заложенная в самом плане межзадачная зависимость (interfaces-блок плана явно требует такого импорта). Атомарность коммитов по task-границам файлов сохранена: `c500408` содержит только файлы Task 1, `d165802` — только файлы Task 2; оба коммита проходят `npx tsc --noEmit` и `npx eslint` по отдельности после того, как оба набора файлов уже существовали на диске.

## Issues Encountered
- `npx eslint` изначально требовал braces вокруг `onValueChange` callback (`@typescript-eslint/no-confusing-void-expression`) и указывал на отсутствующую зависимость `toggleTheme` в `useMemo` (`react-hooks/exhaustive-deps`) — оба исправлены на месте (явный блок `{}` в колбэке, `useCallback` для `setTheme`/`toggleTheme`), без выхода за рамки плана.
