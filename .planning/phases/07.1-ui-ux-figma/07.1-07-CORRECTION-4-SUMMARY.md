## Accomplishments

### 1. `components/charts/BloodPressureLineChart.tsx` (rewritten)

- **Smooth curves:** replaced `moveTo`/`lineTo`-only paths with `buildSmoothPath()`, a
  hand-rolled Catmull-Rom-to-Bezier spline builder (Skia has no built-in equivalent) — for each
  interior segment P1→P2, computes control points `P1 + (P2-P0)/6` and `P2 - (P3-P1)/6`, clamping
  the missing neighbor at each end to the adjacent point.
- **Area fill:** `buildFillPath()` closes the smooth curve down to the chart's bottom edge and
  back to the start x, filled with a vertical `<LinearGradient>` (`${SYSTOLIC_COLOR}4D` → `
  ${SYSTOLIC_COLOR}00`, matching the Figma SVG's `stop-opacity="0.3"` → `"0"`), applied to the
  systolic series only (see decision above).
- **Dots:** each reading's systolic and diastolic points get a small filled circle
  (`r=3.5`) in the series color plus a larger circle (`r=4.5`) underneath acting as a
  border/cutout ring, since Skia's `<Circle>` has no combined stroke+fill.
- **Grid:** 3 horizontal dashed reference lines (one per Y-axis label) and 6 vertical dashed
  guide lines, both via `<DashPathEffect>`, using a low-opacity theme-derived neutral color
  instead of the Figma-literal purple tint (see decision above).
- **Axis labels:** Y-axis (3 labels, computed from the actual min/max of the visible
  systolic+diastolic value range) rendered in a fixed 28px-wide column left of the `Canvas`;
  X-axis (up to 4 labels, evenly spaced across the actual sorted reading timestamps, `HH:mm` via
  `date-fns`'s `format` — same call `ReadingRow` already uses) rendered below the `Canvas`. Both
  follow `SugarByHourChart.tsx`'s established pattern: absolutely-positioned `Text` in a plain
  `View`, not drawn inside the Skia tree.
- Kept the `sorted.length < 2` early-return-null guard unchanged (need at least 2 points for a
  line).
- No `Props` shape change — still `{ readings, height? }` — so `HomeBloodPressureSummary.tsx`'s
  call site (`<BloodPressureLineChart readings={readings} />`) needed no edit; the new
  labels/grid render in space the component claims for itself around the existing `height`-tall
  `Canvas`, not by growing the canvas.
