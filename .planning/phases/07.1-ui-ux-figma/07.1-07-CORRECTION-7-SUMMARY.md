## 2. Часовой чарт (`components/charts/SugarByHourChart.tsx`)

**Fallback-значения для часов без реального показания** (явный запрос
пользователя), приоритет:
1. Реальное показание всегда побеждает для своего часа.
2. Если реального показания в этом часу нет — "перенос вперёд" (carried
   forward) последнего реального показания РАНЬШЕ этого часа в тот же день
   (упрощённая имитация ступенчатого CGM-тренда).
3. Если реальных показаний в этот день ещё не было вообще (даже раньше) —
   оценка `estimateGlucoseFromMeals` по еде, съеденной в этот час или
   раньше, с синтетическим "сейчас" = конец часа.
4. Если ни того ни другого нет — час остаётся пустым (старый нейтральный
   вид трека сохранён как есть).

Оба fallback-вида рисуются с непрозрачностью `0.5`
(`getColor("primary"/"destructive", 0.5, theme)`) — тот же приём "≈ = меньше
уверенности", что уже используется в проекте для оценок. **Ни один fallback
не попадает ни в какой агрегат**: значения бакетов используются только для
локального `maxValue` (масштаб самого чарта) и никогда не смешиваются с
`weekReadings`, недельным средним или дневным мин/макс тайлов "Низкий"/
"Высокий" — проверено вручную (`grep` по потоку данных, см. раздел
`verify` в задании): `estimateGlucoseFromMeals` используется только внутри
`SugarByHourChart.tsx`; недельное среднее (`HomeGlucoseHeroCard.tsx`) и
дневной мин/макс (`HomeGlucoseSummary.tsx`) читают исключительно свои
собственные "сырые" пропы `weekReadings`/`readings`, полученные напрямую из
Convex.

**Красный градиент сверху для баров вне нормы** (явный запрос пользователя):
Skia `LinearGradient` на `Path` бара, стопы
`[destructiveColor, fillColor, fillColor]` на `positions={[0, 0.35, 1]}` —
воспроизводит Figma SVG `#E94545 → нормальный цвет заливки` на ~35% высоты
бара. `destructiveColor` берётся через `getColor("destructive", opacity,
theme)`, а не как литеральный hex: тёмная палитра уже содержит `destructive
= #E94545` буквально (`lib/ui/palettes.ts`), так что через токен получаем и
темизируемость, и точное соответствие Figma в тёмной теме одновременно.
Применяется и к реальным, и к fallback-барам вне нормы (это решение о
цвете, а не о целостности данных) — fallback-бары используют
0.5-непрозрачную версию обоих стопов.

**Маркеры приёмов пищи** (явный запрос пользователя): для каждого часа, в
который был залогирован приём пищи в выбранный день, над баром рисуется
кружок `14px` фиксированного цвета `#C9F14C` (акцент-лайм, тот же приём
"фиксированный декоративный Figma-цвет", что и градиент
`HomeCalorieOverviewCard.tsx`) с иконкой `UtensilsIcon` из
`lucide-react-native` (НЕ `utensils-crossed`) внутри, `8px`, тёмный цвет
`#151810` для контраста. Рендерятся как обычные RN `View` в отдельном ряду
НАД `Canvas` (тот же приём наложения не-Skia контента, каким уже
пользовались подписи оси X), а не внутри самого Skia-дерева.

**Шаг подписи оси X**: `HOUR_LABEL_STEP` 4 → 3, подписи теперь `HH:00` и
сдвинуты так, чтобы показывать ровно `3:00, 6:00, … 24:00` (условие фильтра
`(hour + 1) % 3 === 0`, текст `${hour + 1}:00`) вместо старых "голых" чисел
`0, 4, 8…` — 8 равномерных подписей, как в Figma.

Новые опциональные пропы `meals`, `dayStart`, `baselineReadings` — все по
умолчанию пустые/`undefined`, так что существующие вне-скоуповые
потребители (`app/(home)/day/[date].tsx`,
`app/(settings)/observedPatient/[patientId].tsx` — оба передают только
`readings`) продолжают компилироваться без изменений и просто не получают
fallback-баров/маркеров (см. `grep -rln "HomeGlucoseSummary\|SugarByHourChart"`).

## 3. Новая карточка-герой "Глюкоза" (`components/home/HomeGlucoseHeroCard.tsx`)

Фиксированный декоративный градиент (НЕ через `getColor()`/тему — та же
осознанная конвенция, что и `HomeCalorieOverviewCard.tsx`'s
`getCardGradientColors`): тёмная тема воспроизводит 3-стоповый Figma-градиент
`rgb(72,21,52) → rgb(190,66,125) → rgb(193,164,189)` на
`locations=[0.0667, 0.5024, 1]` — исходный CSS-стоп `117.87%` клэмпнут к
`1.0` (бокс не может отрисовать стоп за своими границами, а видимая разница
несущественна). Светлая тема без Figma-референса — собственная, более
мягкая адаптация той же розово-бордовой гаммы (`0.35`/`0.28` альфа),
растворяющаяся в `getColor("base", undefined, theme)`, по той же схеме
"известная гамма → поверхность темы", что и светлый градиент карточки
калорий.

Весь текст и цвет тик-рисок идут через `getColor("foreground", …, theme)`
(не хардкод белого) — та же логика, что у карточки калорий: в тёмной теме
`foreground` почти белый, в светлой — тёмный, читается на обоих вариантах
градиента.

**Текущее значение**: последнее реальное показание сегодня, иначе
`≈`-оценка `estimateGlucoseFromMeals`, иначе `—`. Размер `48` из проекта
недостаточен (максимум в `FontSize`-union), поэтому `fontSize: 60`/
`lineHeight: 64` заданы точечным inline-переопределением стиля, а не новым
членом enum ради одного экрана.

**Недельное среднее ("N сред/нед")**: считается **только** из реальных
`weekReadings` (оценка никогда не подмешивается) — то же округление, что и
`estimateGlucoseFromMeals` (1 знак для `mmol/L`, целое для `mg/dL`),
отображается в единице текущего значения (по умолчанию `mmol/L`, если
текущего значения нет).

**Тик-виджет тренда — явно помеченная трактовка сессии, однозначного
Figma-спека нет (см. задание)**: реализован как `14` нейтральных тик-рисок
темы (`getColor("foreground", 0.35, theme)`, `2×20px`) в фиксированном ряду
`72×40`, плюс один акцентный маркер темы
(`getColor("primary", undefined, theme)` — намеренно НЕ буквальный
Figma-лайм, чтобы корректно смотрелось и в светлой теме), собранный из
CSS-треугольника-каретки + бара `2×22px`. Горизонтальная позиция маркера —
доля текущего значения внутри диапазона `[min, max]` РЕАЛЬНЫХ показаний за
неделю (пересчитано в `mmol/L` для самой доли, независимо от единицы
отображения), клэмп к `[0,1]`, если текущее значение выходит за пределы
недельного диапазона, `0.5` при `min === max`. Если в будущем чекпоинте
пользователь укажет другую трактовку виджета — меняется только
`markerRatio` внутри `HomeGlucoseHeroCard.tsx`, остальной код от этого не
зависит.

## 4. Тайлы "Низкий"/"Высокий" (`components/home/HomeGlucoseRangeTile.tsx`)

Новый компонент-сосед, а не расширение `HomeNutrientGlowCard.tsx`: контракт
той карточки — пара `value`/`target` (доля/прогресс), которая не подходит
для формы "значение + единица + иконка-стрелка направления, без target".
Общая техника свечения (тёмный inset / светлый ambient) вынесена в
`lib/ui/getNutrientGlow.ts` (см. п.5) — переиспользуется без дублирования.

Цвета свечения (буквальные Figma hex, та же конвенция "фиксированный
декоративный цвет", что и у трёх нутриент-тайлов): Низкий = `#869781`
(тёмная) / `rgba(134,151,129,0.28)` (светлая); Высокий = `#B84244`
(тёмная) / `rgba(184,66,68,0.28)` (светлая). Иконки: lucide
`ArrowDownRightIcon` (Низкий) / `ArrowUpRightIcon` (Высокий), в правом
верхнем углу строки заголовка.

Значения: `Math.min`/`Math.max` только по РЕАЛЬНЫМ показаниям СЕГОДНЯШНЕГО
дня (тот же массив `readings`, что раньше рендерил список `ReadingRow`) —
без оценок, без carried-forward/estimate-значений чарта.

**Пустое состояние (у Figma нет спека для него)**: выбор этой сессии —
скрывать оба тайла целиком, если за день ещё нет ни одного реального
показания, вместо отображения пары тайлов с прочерком — две заметные
светящиеся плитки без содержательных данных выглядели бы хуже, чем их
отсутствие.

## 6. Избежание вложенных touchable

`HomeGlucoseHeroCard` и `HomeGlucoseRangeTile` — чистые деревья
`View`/`LinearGradient` без собственного `Button`/`Pressable` (в отличие от

Это позволяет `HomeGlucoseSummary` по-прежнему оборачивать весь контент
карточки в один внешний `Button`→`Link` на `/glucoseLog` (прежнее поведение
"тап по карточке открывает полную историю") без конфликта вложенных
`Pressable`. Новой интерактивности нигде не добавлено (D-04 подтверждён):
чарт, карточка-герой и её тренд-виджет остаются чисто визуальными/
статичными.

`HomeGlucoseSummary` теперь получает три новых опциональных пропа:
