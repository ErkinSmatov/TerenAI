## Accomplishments

### 1. `components/ui/CircularProgress.tsx` — new optional props, default behavior preserved

Added two new optional props, both no-ops when omitted so `HomeSummaryCardBig` and
`HomeSummaryCard` (the only other two callers) render pixel-identical to before this change:

- `gradientColors?: [string, string]` — when present, renders a Skia `<LinearGradient>` shader
  as a child of the stroked `<Path>` instead of passing a flat `color`. The gradient spans the
  path's own bounding square diagonal (`(0,0)` to `(size,size)`, in the pre-rotation coordinate
  space that the enclosing `<Group>`'s `-90deg` transform then rotates along with everything
  else).
- `endCap?: { color, borderColor, borderWidth, radius }` — when present, draws a small bordered
  circle (two stacked `<Circle>`s: an outer one in `borderColor` and a smaller inner one in
  `color`) at the exact point where the visible filled arc currently ends. This point is
  computed via `Skia.ContourMeasureIter(path, false, 1).next()` then
  `contour.getPosTan(end.value * contour.length())` inside a `useDerivedValue` — not manual
  trigonometry — so it tracks the same animated `start`/`end` trim SharedValues the stroked
  `Path` already uses, and stays correct regardless of the `Group`'s rotation transform.

When used with an array of progress values (multi-segment rings), `gradientColors` applies
uniformly to every segment and `endCap` renders only on the last segment — a generalization
beyond this card's single-value use case, made because it was free to support and avoids
over-narrow typing on the shared primitive.

### 2. `components/home/HomeCalorieOverviewCard.tsx` — fixed gradients, 50/50 layout, steps re-layout

- Removed the ratio/theme-conditional `ringColor` (`primary` accent / `destructive` over
  target) entirely. The ring now always renders `CALORIE_RING_GRADIENT = ["#EE6A22",
  "#FEE8D9"]` via the new `gradientColors` prop, plus `CALORIE_RING_END_CAP = { color:
  "#F19062", borderColor: "#FFFFFF", borderWidth: 2, radius: 8 }` via the new `endCap` prop —
  fixed regardless of theme or over-target status.
- `ringColumn` style changed from a fixed `width: 132, height: 132` box to `flex: 1,
  aspectRatio: 1`, matching `macrosColumn`'s `flex: 1` so the two columns split the middle row
  exactly 50/50. The `size` prop was removed from the `CircularProgress` call so it continues
  to auto-size via its existing `onLayout` measurement, now measuring the wider 50%-width
  column instead of a fixed 132px box.
- `MacroRow`'s `color: string` field replaced with `gradientColors: [string, string]`. The old
  flat `color` prop is gone, not kept as a fallback.
- `ProgressBar`'s flat `Animated.View` fill (`backgroundColor: color`) replaced with
  `Animated.createAnimatedComponent(LinearGradient)` (the same `expo-linear-gradient` import
  already used for the card's own background), rendering `colors={gradientColors}` with the
  existing `fillStyle` width-animation applied unchanged to the animated gradient view.
- Steps header row re-laid-out from icon+steps-count-together-on-left / distance-trailing to a
  three-slot `justify-content: space-between` row: step count (left), `FootprintsIcon` (center),
  distance + "км" folded into one right-aligned label (right) — directly above the full-width
  bar, which now renders `STEPS_GRADIENT = ["#C9F14C", "#F7F1E3"]` via `gradientColors` instead
  of the theme accent token. The now-unused `stepsBarRow`/`stepsDistanceText` wrapper styles
  were removed since the bar no longer shares a row with trailing text.

### 3. `components/home/HomeMacroSummary.tsx` — literal hex macro gradients

Replaced the three `getColor("protein"/"fat"/"carb", undefined, theme)` calls with three
module-scope literal gradient constants (`PROTEIN_GRADIENT`, `FAT_GRADIENT`, `CARB_GRADIENT`),
passed through the `macros` array's new `gradientColors` field. `useThemeContext`'s `theme`
value is no longer read in this file (it was only used for the removed `getColor` calls) —
`useThemedStyles(createStyles)` still resolves theme internally for the container style.

### 4. `.planning/phases/07.1-ui-ux-figma/07.1-UI-SPEC.md`

Updated the "Home — Calorie Overview Card" section's "Structure" and "Color contract"
paragraphs to describe the corrected 50/50 layout, the re-laid-out steps header, and the fixed
literal hex gradients (replacing the theme-token description from the first correction round).
Added a reconciliation note at the top of the section explaining that this is a supersede, not
a silent overwrite, and why the newer instruction wins. Also added a scoped exception to the
global "Accent reserved for" list (this card's ring/steps-bar fills no longer use the accent
token, unlike `HomeSummaryCardBig`/`HomeSummaryCard` elsewhere) and documented the two new
`CircularProgress` props.
