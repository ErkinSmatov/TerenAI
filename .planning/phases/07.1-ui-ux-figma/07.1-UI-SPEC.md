## Typography

Two font families, two weights each (Regular / SemiBold). Do not introduce additional weights.

| Role | Font | Size | Weight | Line Height |
|------|------|------|--------|-------------|
| Label / caption | Manrope | 12px | 400 (Regular) | 1.4 |
| Body | Manrope | 16px | 400 (Regular) | 1.5 |
| Heading | Manrope | 20px | 600 (SemiBold) | 1.2 |
| Display — metric value | Outfit | 48px | 600 (SemiBold) | 1.1 |

Screen titles reuse the Heading role (20px/SemiBold) — no separate screen-title size. The hero glucose metric (60px in Figma) and the calories total (42px in Figma) are both instances of the single Display role at its one fixed size (48px); visual weight difference between "hero" and secondary display numbers comes from layout/placement and color emphasis, not from a second display size.

Numeric values anywhere on redesigned screens (calorie totals, macro grams, glucose readings, steps) use Outfit. All non-numeric UI text (labels, buttons, section titles, body copy) uses Manrope.

## Home — Calorie Overview Card (added post-D-03 checkpoint, 2026-09-17; corrected in a 2nd
D-03 round the same day)

Retroactive contract for `components/home/HomeCalorieOverviewCard.tsx`, added after the D-03
human-verification checkpoint on Главная. The user rejected the original 3-block layout
(big calorie ring card + row of 3 macro tiles + separate movement/steps card) in favor of a
single merged card matching Figma node `863:5405` exactly. This section documents that node's
contract, which was not captured when the rest of this spec was originally written.

**Reconciliation note (2nd D-03 correction round):** the first correction pass approximated
the ring/macro-bar/steps-bar fills with theme-derived semantic tokens (`primary` accent,
`protein`/`fat`/`carb`). After closer pixel-level review against Figma, the user gave direct,
specific hex-gradient corrections for all three, superseding the "Color contract" paragraph
that originally lived in this section. The direct, most-recent, most-specific user instruction
wins — see the corrected contract below. Do not re-theme these values.

**Structure** (flexbox reimplementation of the 350×250 Figma reference, not absolute
positioning):
- Card: `border-radius: 24px`, own gradient background (see Gradient below — does not use
  `Card`'s flat theme-token background), hairline border + `getShadow("sm")` matching the
  standard `Card` treatment, `padding: 20px`.
- Top: title "Калории" — Manrope SemiBold 16px, theme foreground.
- Middle row: ring column and macro column split the row exactly **50/50** (`flex: 1` on both,
  ring column additionally `aspectRatio: 1` to stay square as it's sized from measured column
  width — no more fixed 132px box). Left = circular ring (reused `CircularProgress`,
  `strokeWidth: 8`, auto-sized via its existing `onLayout` measurement, gradient stroke + a
  scrubber-style end-cap dot — see Color contract) showing calories-consumed/target ratio,
  centered overlay text = calories **remaining** (target − consumed, can go negative, Outfit
  40px) + "Осталось" caption (Manrope 12px, foreground @ 60% opacity). Right = 3 macro rows in
  fixed order **Белки, Жиры, Углеводы**, each: label (Manrope SemiBold 12px, foreground @ 65%),
  horizontal rounded bar (track 9px/radius 5, fill 5px/radius 2.5, foreground @ 12% track
  opacity, gradient fill — see Color contract), value `"{consumed}/{target}"` (consumed: Outfit
  SemiBold 20px foreground; target: Outfit 12px foreground @ 45%).
- Bottom row: left = "Всего" (Manrope 12px, foreground @ 65%) above calorie **target**
  (Outfit SemiBold 20px). Center = steps block, three-slot header row
  (`justify-content: space-between`) above a full-width bar: **left** = steps count (Outfit
  SemiBold 12px), **center** = `FootprintsIcon` (20px, reused from `HomeMovementSummary`),
  **right** = distance + "км" unit together (Outfit 12px, foreground @ 45%, e.g. "3.4 км") —
  folded into the header row, no longer trailing after the bar. Below: full-width thin bar
  (3px/3px, same track token, gradient fill — see Color contract). Right = "Съедено" (Manrope
  12px, foreground @ 65%, right-aligned) above calorie **consumed** (Outfit SemiBold 20px,
  right-aligned).

**Color contract (corrected, 2nd D-03 round):** the calorie ring, all three macro bars, and the
steps bar use **fixed literal hex gradients**, NOT `getColor()`/theme tokens, and NOT the
consumed/over-target status logic other rings in this app use (`HomeSummaryCardBig`/
`HomeSummaryCard`'s destructive-over-target rule does NOT apply here). Same values in light AND
dark theme:
- Calorie ring stroke: gradient `#EE6A22` → `#FEE8D9`, plus a small end-cap "handle" dot at the
  exact end of the visible filled arc — fill `#F19062` with a `2px` white (`#FFFFFF`) border,
  tracking the animated progress value (computed via Skia contour measurement, not manual
  trigonometry, so it self-corrects if the ring's rotation transform ever changes).
- Белки (protein) bar: `#F1853C` → `#F7F1E3`.
- Жиры (fat) bar: `#8489DA` → `#F7F1E3`.
- Углеводы (carbs) bar: `#F47F6E` → `#F7F1E3`.
- Steps bar: `#C9F14C` → `#F7F1E3` (this happens to equal the dark-theme `primary` accent value,
  but is now hardcoded literally and must NOT change if the theme's `primary` token changes).

This supersedes the original "Color contract" paragraph from the first correction round, which
described these as theme-derived (`primary` accent, `protein`/`fat`/`carb` semantic tokens).
That description no longer matches the implementation — do not revert to it.

**`CircularProgress` extension:** `components/ui/CircularProgress.tsx` gained two new OPTIONAL
props to support the ring above: `gradientColors?: [string, string]` (renders a Skia
`<LinearGradient>` shader child on the stroked `<Path>` instead of a flat `color`) and
`endCap?: { color, borderColor, borderWidth, radius }` (draws the scrubber dot at the current
end-of-arc point via `Skia.ContourMeasureIter`/`getPosTan`). Both are no-ops when omitted —
`HomeSummaryCardBig` and `HomeSummaryCard` do not pass them and render pixel-identical to
before this correction.

**Gradient (own asset, not a semantic token):**
- Dark: `linear-gradient(142deg, rgb(192,91,23) 3.42%, rgb(27,27,27) 52.64%)` — reproduced
  from the Figma dark reference verbatim (decorative "hero" identity, not derived from
  `orange`/`background` tokens).
- Light (no Figma reference existed for this — user explicitly requested a distinct light
  variant rather than reusing the dark gradient, decided at the D-03 checkpoint): same ~142°
  diagonal, from `rgba(249,115,22,0.22)` (the existing `orange` token at 22% opacity) to the
  theme's `base` token (white), preserving the same warm-orange "hero" identity translated to
  a light surface.

**Steps goal default:** the app has no per-user daily steps-goal config (unlike calorie/macro
targets, which come from `profiles.targets`). A fixed default of **10000 steps** is used only
to compute the steps-bar fill ratio (`calcRatio(steps, 10000)`, clamped 0–1). Documented here
as a Claude's Discretion call and a candidate for a future per-user config if the product adds
one — not a data model change in this correction.

**Scope note:** this card replaces the old 3-block layout (`HomeSummaryCardBig` +
`HomeSummaryCard` row + standalone `HomeMovementSummary`) on Главная only. The two
not-yet-redesigned screens that reuse `HomeMacroSummary` (`app/app/(home)/day/[date].tsx` —
Дневник, and `app/app/(settings)/observedPatient/[patientId].tsx` — наблюдатель) keep
rendering the previous two-block layout (`HomeMacroSummary` + separate `HomeMovementSummary`)
until their own redesign waves — `movement` is an optional prop on `HomeMacroSummary` for
exactly this reason. `HomeSummaryCardBig` and `HomeSummaryCard` were deleted in the 3rd D-03
correction round (see next section) — their old "Качество"/fiber/sugar/sodium tiles now render

D-04 still applies: this card, including the new steps progress bar, is purely static/visual —

## Home — Blood Pressure Chart (4th D-03 correction round, 2026-09-21)

Retroactive contract for `components/charts/BloodPressureLineChart.tsx`. The user reviewed the
chart against Figma node `822:5258` ("BarLineChart", a generic reference component) and
rejected the prior straight-line-segment/no-decoration implementation entirely in favor of this
node's smooth-curve + area-fill + dotted-grid look. `HomeBloodPressureSummary.tsx` (the only
consumer — confirmed via `grep -rln "BloodPressureLineChart\|HomeBloodPressureSummary"`, no
other screen renders either file) keeps its own external "Давление" title header; the chart
component itself never renders a title, matching the pre-correction contract.

**Curve technique:** Skia has no built-in "smooth path through arbitrary points" primitive, so
both series (systolic/diastolic) are drawn with a hand-rolled Catmull-Rom-to-Bezier spline
(`buildSmoothPath`): for each interior segment P1→P2, the cubic control points are
`P1 + (P2-P0)/6` and `P2 - (P3-P1)/6`, with the missing neighbor at each end clamped to the
adjacent point. Replaces the old `moveTo`/`lineTo`-only path.

**Two-line decision (explicit user choice — keep both series):**
- Systolic: `#8979FF`, the literal Figma violet (fixed hex, NOT `getColor()`/theme — same
  literal-hex-for-figma-color treatment as the calorie card's gradients).
- Diastolic: `#FF8A65`, a warm coral chosen for this correction — reads as a clearly distinct
  "second series" next to the violet on both light and dark surfaces without clashing (avoided
  blue/indigo hues, which sit too close to violet on the hue wheel).
- **Area fill — systolic only.** Both series' values move closely together (systolic just above
  diastolic at all times), so filling both would produce two overlapping translucent bands that
  read as a muddy blob rather than two distinct trends. Only the systolic (upper) line gets the
  gradient fill; diastolic renders as stroke + dots with no fill. Documented deviation from the
  literal Figma reference (a single-line component), per user's own two-line/judgement-call
  instruction.
- Fill gradient: vertical `LinearGradient` (`vec(0,0)` → `vec(0, height)`), stops
  `${SYSTOLIC_COLOR}4D` (≈30% alpha, `4D` hex = 77/255) at top → `${SYSTOLIC_COLOR}00` (0% alpha)
  at bottom — matches the Figma SVG's `stop-opacity="0.3"` → `"0"` vertical gradient exactly,
  expressed as an 8-digit hex alpha suffix instead of an `rgba()` string (Skia's `colors` prop
  accepts either; hex-alpha was more direct here since the base color is already a literal hex).

**Data-point dots:** filled circle `r=3.5` in the series color, with a `r=4.5` circle
underneath acting as a 1px border/"cutout" ring (drawn largest-first via two stacked `<Circle>`
components, since Skia's `<Circle>` has no separate `stroke`+`fill` composition like SVG).
Border color is `getColor("base", undefined, theme)` — the same card-background token
`Card.tsx` uses — rather than the literal Figma `#1A1F26`: this codebase's dark `base` token is
`#272C35`, not `#1A1F26`, so using the theme token produces a true "cutout into the card
background" effect on our actual dark surface instead of a slightly-mismatched hardcoded value.
Light theme gets the same treatment for free (`base` = white), satisfying the brief's ask for a
"subtle ring, not a hard dark line" on light cards without a separate hardcoded light constant.

**Grid:**
- 3 horizontal dashed reference lines (`DashPathEffect intervals={[4, 4]}`), one per Y-axis
  label position (see below).
- 6 vertical dashed guide lines (`DashPathEffect intervals={[2, 2]}`) at even intervals across
  the chart width — purely decorative rhythm guides, not tied to data values.
- Both grid layers use `getColor("foreground", 0.08, theme)` instead of the Figma reference's
  literal dark-background-tuned `#D9D9FF` — a low-opacity neutral foreground reads correctly as
  "faint grid" on both our light and dark surfaces, whereas the purple-tinted Figma constant was
  designed against that mockup's specific dark background only.

**Axis labels** (`family="outfit"`, `size="12"`, `mutedForeground` color — same label-rendering
pattern as `SugarByHourChart.tsx`: absolutely-positioned `Text` in a plain `View` below/beside
the `Canvas`, not drawn inside the Skia tree):

### Calorie ring end-cap clipping fix

`components/ui/CircularProgress.tsx`: the Skia `<Canvas>` was sized to exactly the ring's own
reported layout box, but the optional `endCap` "handle" dot (used only by
`HomeCalorieOverviewCard.tsx`'s calorie ring, `radius: 8` vs `strokeWidth: 8`) is drawn with a
radius larger than half the stroke width, so it visually pokes `endCap.radius - strokeWidth/2`
px past the stroke's own outer edge — which already touches the Canvas boundary. Skia clips
Canvas contents to its own pixel bounds, cutting off the top of the dot.

Fix: `overflow = max(0, endCap.radius - strokeWidth/2)` (0 when no `endCap` is passed — the
common case for every other caller, e.g. `HomeDaySelector`). The Canvas renders
`overflow * 2` larger than the component's own reported layout box, absolutely positioned and
centered (`top/left: -overflow`) so it doesn't disturb sibling flex layout (`ringColumn` in
`HomeCalorieOverviewCard.tsx` is unaffected — it sizes from flex/aspectRatio, not from
`CircularProgress`'s intrinsic size). The circle path's center and the `Group`'s rotation
origin shift by `+overflow` to stay centered in the enlarged canvas. When `overflow` is 0 (no
`endCap`), all of this collapses to the exact pre-fix positions — byte-for-byte identical
rendering for every other `CircularProgress` consumer.

### Hourly chart extensions (`SugarByHourChart.tsx`)

- **Fallback bars for hours without a real reading**, in priority order: (a) the most recent
  real reading earlier the same day, carried forward step-style (CGM-trend simplification); (b)
  if no earlier real reading exists that day, `estimateGlucoseFromMeals` evaluated at the end of
  that hour, using meals logged in or before it. Real readings always win for their own hour.
  Both fallback kinds render at `0.5` fill opacity (`getColor("primary", 0.5, theme)`/
  `getColor("destructive", 0.5, theme)`) — the same "≈ = reduced-certainty" visual convention
  used elsewhere for estimates. **Neither fallback ever enters an aggregate** — they're computed
  per-bar purely for this chart's local `maxValue` scaling, never merged into `weekReadings`,
  the weekly average, or the day min/max used by the range tiles (see
  `estimateGlucoseFromMeals.ts`'s own documented constraint).
- **Red gradient top on out-of-range bars**: Skia `LinearGradient` on the bar `Path`, stops
  `[destructiveColor, fillColor, fillColor]` at `positions={[0, 0.35, 1]}` — reproduces the Figma
  SVG's `#E94545 → normal fill` fade at ~35% of bar height. `destructiveColor` comes from
  `getColor("destructive", opacity, theme)` rather than a literal hex: the dark palette's
  `destructive` token already equals `#E94545` exactly, so this stays themeable without
  diverging from the Figma value in dark mode. Applies to real AND fallback out-of-range bars
  alike (color decision only, not a data-integrity one) — fallback bars use the `0.5`-opacity
  variant of both gradient stops.
- **Meal marker badges**: a small `14px` circle (`#C9F14C`, fixed literal — same
  "fixed-decorative-Figma-color" convention as `HomeCalorieOverviewCard.tsx`'s gradient) above
  the bar for every hour a meal was logged that day, containing lucide's `UtensilsIcon` at `8px`
  in a dark contrasting color (`#151810`). Rendered as absolutely-positioned RN `View`s in a
  dedicated row above the `Canvas` (same non-Skia overlay technique the chart already used for
  its axis labels), not inside the Skia tree.
- **X-axis label step**: `HOUR_LABEL_STEP` 4 → 3, with labels now formatted `HH:00` and shifted
  to show `3:00, 6:00, … 24:00` (filter condition `(hour + 1) % 3 === 0`, label text
  `${hour + 1}:00`) instead of the old bare-number `0, 4, 8…` labels — 8 evenly-spaced labels,
  matching Figma exactly.
- New optional props `meals`, `dayStart`, `baselineReadings` — all default to empty/undefined so
  existing out-of-scope callers (`day/[date].tsx`, `observedPatient/[patientId].tsx`, both only
  pass `readings`) keep compiling and simply don't render fallback bars/markers.

### New "Глюкоза" hero card (`HomeGlucoseHeroCard.tsx`)

- Fixed decorative gradient (not `getColor()`/theme, same rationale as
  `HomeCalorieOverviewCard.tsx`'s `getCardGradientColors`): dark theme reproduces Figma's 3-stop
  `rgb(72,21,52) → rgb(190,66,125) → rgb(193,164,189)` at `locations=[0.0667, 0.5024, 1]` (the

  same pink/mauve hue family (at `0.35`/`0.28` alpha) into `getColor("base", undefined, theme)`,

  gradient.
- All text/tick colors go through `getColor("foreground", …, theme)` (not hardcoded white) —
  same reasoning as the calorie card's own text, which stays legible against both the dark
  Figma-literal gradient and the new lighter light-theme variant.
- Current value: most recent real reading today, else the `≈` `estimateGlucoseFromMeals` value,
  else `—`. `48`-sized `Text` forced to `fontSize: 60`/`lineHeight: 64` via inline style override

  `HomeGlucoseHeroCard.tsx`'s `markerRatio` calculation needs to change — nothing else in this
