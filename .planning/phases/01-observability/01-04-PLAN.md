<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Машина разработчика → Sentry API | `sentry-cli` выполняется с auth-токеном в окружении оболочки |
| Сборщик EAS → артефакты релиза | Sourcemaps с исходным кодом TS выгружаются во внешний сервис |
| TestFlight-сборка → тестеры | Собранный бинарник с разделом диагностики попадает к посторонним людям |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-17 | Information disclosure | `SENTRY_AUTH_TOKEN` при вызове `sentry-cli` | mitigate | Токен читается из переменной окружения оболочки пользователя; агенту запрещено запрашивать значение в чат и передавать его в командной строке через `--auth-token` (аргументы попадают в историю и логи) |
| T-01-18 | Information disclosure | Sourcemaps в Sentry | accept | Исходники TS становятся доступны участникам организации Sentry. Это прямая цель OBS-03; ограничение доступа обеспечивается составом организации |
| T-01-19 | Tampering | Молча непрошедшая загрузка sourcemaps | mitigate | Проверка выполняется на стороне Sentry через `sentry-cli releases files list`, а не по отсутствию ошибок в логе сборки; при пустом списке заливка в TestFlight блокируется |
| T-01-20 | Repudiation | Смешение событий локальной сборки и TestFlight | mitigate | Task 1 требует заменить метку окружения на `local-release`; Task 3 отдельно проверяет, что в TestFlight-событиях окружение равно `testflight` |
| T-01-21 | Information disclosure | Раздел диагностики у внешних тестеров | accept | Действия отправляют только синтетические события и не раскрывают данные (обосновано в T-01-13 плана 01-03) |
</threat_model>
