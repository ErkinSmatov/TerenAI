Списки писать явно, а не собирать через `date-fns`, — так конфигурация остаётся статичной и не зависит от порядка импортов.

    3. **Состояние месяца.** `const [visibleMonth, setVisibleMonth] = useState(() => new Date());` и `const bounds = getLocalMonthBounds(visibleMonth);`. Проп `onMonthChange={({ year, month }) => setVisibleMonth(new Date(year, month - 1, 1))}` — у `react-native-calendars` месяц в колбэке приходит с единицы, поэтому вычитание единицы обязательно.

    4. **Метки заполненных дней.** `useQuery(api.meals.getMonthMeals.default, { dayStartsUtc: bounds.dayStartsUtc })`. Из результата собрать `markedDates`: для каждого индекса `i`, где массив блюд непуст, поставить `{ marked: true, dotColor: getColor("mutedForeground", 0.4) }` по ключу `bounds.monthDates[i]`. Точка намеренно серая, а не акцентная: акцент (`primary`/`blue`) по UI-SPEC зарезервирован ровно за заливкой выбранной даты и точкой «сегодня», и не должен расползаться на маркеры данных. Пока запрос возвращает `undefined`, передавать пустой объект `{}` — календарь должен рисоваться сразу, а не ждать данных.

    5. **Диапазон.** `maxDate` — сегодняшняя локальная дата в формате `YYYY-MM-DD` (собрать теми же `getFullYear`/`getMonth`+1/`getDate` с `padStart`, что и остальной код проекта; `toISOString().slice(0, 10)` не использовать — он даёт UTC-дату и в части часовых поясов запретит выбрать сегодняшний день). Нижней границы не ставить — листание назад свободное. Это решение планировщика по оставленному на усмотрение вопросу о диапазоне истории: данных о будущем не бывает, а вперёд смотреть незачем; назад — сколько угодно.

    6. **Тема.** Проп `theme` с сопоставлением токенам `getColor`: `calendarBackground` → `base`, `dayTextColor` → `foreground`, `monthTextColor` → `foreground`, `textSectionTitleColor` → `mutedForeground`, `textDisabledColor` → `getColor("mutedForeground", 0.4)`, `selectedDayBackgroundColor` → `primary`, `selectedDayTextColor` → `base`, `todayTextColor` → `primary`, `arrowColor` → `foreground`. Новых цветовых токенов не заводить.

    7. **Переход.** `onDayPress={({ dateString }) => router.push({ pathname: "/app/(home)/day/[date]", params: { date: dateString } })}` — `dateString` уже приходит в формате `YYYY-MM-DD`, ровно в том, который парсит экран дня.

    8. **Обёртка.** Календарь положить в `Card` из `components/ui/Card` (белая поверхность на фоне `background`, по правилу «вторичный цвет — поверхности» из UI-SPEC) с `firstDay={1}`, чтобы неделя начиналась с понедельника — согласованно с `HomeDaySelector`.
