    1. **Параметр маршрута.** `const { date } = useLocalSearchParams<{ date: string }>();` — строка `YYYY-MM-DD`.

    2. **Парсинг даты (критично).** Разобрать строку вручную: `const [year, month, day] = date.split("-").map(Number);` и построить `const target = new Date(year, month - 1, day);`. Использовать `new Date(date)` категорически запрещено: для строки формата `YYYY-MM-DD` спецификация трактует её как полночь UTC, из-за чего в отрицательных смещениях (Америка) экран покажет предыдущий день. Валидация: если строка не матчит `/^\d{4}-\d{2}-\d{2}$/`, либо любое из трёх чисел `NaN`, либо `target` невалидна (`Number.isNaN(target.getTime())`), либо восстановленная из `target` дата не совпадает с исходной строкой (защита от «2026-02-31») — отрисовать состояние ошибки (см. пункт 7) и не выполнять ни одного запроса.

    3. **Границы месяца и индекс дня.** `const bounds = getLocalMonthBounds(target);` и `const dayIndex = day - 1` (нумерация дней месяца с единицы, индекс массива с нуля). Дополнительно утвердить `dayIndex >= 0 && dayIndex < bounds.monthDates.length`, иначе — состояние ошибки.

    4. **Запросы.** Четыре `useQuery` по месячным запросам из блока `<interfaces>`, с аргументами `{ dayStartsUtc: bounds.dayStartsUtc }` для блюд, глюкозы и давления и `{ monthDates: bounds.monthDates }` для движения. Гейты `"skip"` копируют логику главного экрана: глюкоза и давление запрашиваются только при `isGlucometerTrack` (берётся из `useQuery(api.profiles.getProfile.default)` как `profile?.data?.goalTrack === "glucometer"`), движение — только при `Platform.OS === "ios"`. Из каждого результата брать элемент по `dayIndex` через `.at(dayIndex)` с запасными значениями `[]` / `null`, как это уже сделано на главном экране.

    5. **Загрузочное состояние.** Пока `useQuery` блюд возвращает `undefined`, рендерить ту же оболочку с `ScreenHeaderTitle title="Загрузка…"` и `<ScreenMainTitle loading />` — дословный приём из `observedPatient/[patientId].tsx`.

    6. **Отрисовка.** Оболочка `ScreenMain` / `ScreenHeader` + `ScreenHeaderBackButton` + `ScreenHeaderTitle` / `ScreenMainScrollView` с `useScrollY`, как в `glucoseLog.tsx`. Заголовок — `format(target, "d MMMM", { locale: ru })` с заглавной первой буквой (приём из `nutrients.tsx`), размер и начертание задаются самим `ScreenHeaderTitle`/`ScreenMainTitle`, новых типографических ролей не вводить. Содержимое в порядке главного экрана: `Carousel showIndicators` с `HomeMacroSummary` и `HomeMicroSummary`, затем `HomeRecentlyLogged`, затем `HomeMovementSummary` (только на iOS), затем при `isGlucometerTrack` — `HomeGlucoseSummary` и `HomeBloodPressureSummary`. На все карточки передавать `readOnly` — это исторический просмотр, кнопки добавления и ссылки «Все» здесь не нужны, и именно `readOnly` у `HomeMicroSummary` снимает риск ссылки, ведущей на день текущей недели.
       - `HomeMacroSummary` получает `totalMacros={dayTotals.macros}`, `readOnly` И обязательно `targets={profile?.targets ?? undefined}` — без явного пропа при `readOnly` подставятся дефолтные цели из `profilesConfig`, а не собственные цели пользователя.

    7. **Пустое состояние и ошибка.** Если за дату нет ни блюд, ни показаний, ни движения, ни давления — вместо карточек отрисовать центрированный блок из двух `Text` по образцу пустого состояния `HomeGlucoseSummary.tsx` (строки 58-64): заголовок `Нет данных за этот день` (`size="20" weight="600"`) и тело `Записи о питании и показателях за эту дату отсутствуют.
