# Requirements: TerenAI

**Defined:** 2026-08-05
**Core Value:** Пользователь фотографирует еду и через несколько секунд видит достоверные калории и БЖУ — без ручного ввода и поиска по базе.

**Майлстоун v1.3 — «Стабильный билд в TestFlight»:** приложение запускается, гость пользуется им без регистрации, тестер проходит основной сценарий без блокирующих ошибок.

## v1 Requirements

### Наблюдаемость (OBS)

- [ ] **OBS-01**: Краши и необработанные ошибки в релизной сборке попадают во внешний сервис отчётов (не только в `console.error`), с указанием версии сборки и платформы
- [x] **OBS-02**: Существующий хелпер `lib/utils/logError.ts` отправляет ошибки в этот сервис, сохраняя текущее поведение в dev
- [ ] **OBS-03**: Стек-трейсы релизной сборки читаемы (загружены sourcemaps для EAS-билда), а не минифицированы
- [x] **OBS-04**: Команда может собрать production-сборку локально и воспроизвести на ней поведение релиза

### Запуск приложения (BOOT)

- [x] **BOOT-01**: Приложение, установленное из TestFlight на iOS, доходит до первого экрана без краша
- [ ] **BOOT-02**: Отсутствие или опечатка в переменной окружения продакшн-среды не приводит к молчаливому крашу при старте — ошибка видна и диагностируема
- [ ] **BOOT-03**: Все нативные модули, от которых зависит код, объявлены в конфиге production-сборки (нет расхождения между установленным пакетом и подключённым плагином)
- [ ] **BOOT-04**: Причина краша 1.2.1 (1) зафиксирована письменно, чтобы регрессия распознавалась повторно

### Гостевой доступ (GUEST)

- [ ] **GUEST-01**: Новый пользователь при первом запуске попадает в приложение, не видя экрана авторизации
- [ ] **GUEST-02**: Гость проходит онбординг и получает персональные цели по калориям и БЖУ
- [ ] **GUEST-03**: Гость создаёт блюдо по фото и видит рассчитанные калории и БЖУ
- [ ] **GUEST-04**: Данные гостя (профиль, цели, блюда) сохраняются между запусками приложения
- [ ] **GUEST-05**: Пользователь может войти в аккаунт по собственной инициативе из настроек — вход не навязывается
- [ ] **GUEST-06**: Лимит AI-запросов применяется к гостю так же, как к зарегистрированному пользователю
- [ ] **GUEST-07**: Гостевая сессия не ломает подписку: статус RevenueCat корректно соотносится с гостевым пользователем

### Сквозной сценарий тестера (FLOW)

- [ ] **FLOW-01**: Открытие блюда не падает, если продукт отсутствует в базе — блюдо отображается с деградацией, а не с ошибкой всего экрана
- [ ] **FLOW-02**: Ошибка при исправлении блюда через AI показывается пользователю, а не теряется молча
- [ ] **FLOW-03**: Экран недельной истории показывает блюда в правильных днях, включая переход на летнее/зимнее время
- [ ] **FLOW-04**: Тестер проходит путь «онбординг → фото блюда → калории на главном экране» на TestFlight-сборке без блокирующих ошибок

### Дистрибуция (DIST)

- [ ] **DIST-01**: Существует профиль сборки для тестирования, не смешивающий тестовые билды с релизными кандидатами
- [ ] **DIST-02**: Процесс «собрать и залить в TestFlight» описан и воспроизводим по шагам

### Наблюдатель за пользователем (OBSV)

- [ ] **OBSV-01**: Наблюдатель (родитель/ребёнок/врач — одна функциональная роль) подключается к аккаунту пациента через собственный аккаунт (обычный вход/гостевой режим) и постоянный многоразовый код пациента
- [ ] **OBSV-02**: Пациент видит и управляет своим кодом в новом разделе Настроек; один пациент может делиться кодом с несколькими наблюдателями одновременно
- [ ] **OBSV-03**: Наблюдатель может подключиться к нескольким пациентам сразу (несколько кодов) и видит их всех в едином списке наблюдаемых
- [ ] **OBSV-04**: Список наблюдаемых доступен по кнопке в шапке главного экрана (`components/home/HomeHeader.tsx`) и показывает карточку на каждого пациента с сегодняшними данными: глюкоза, количество приёмов пищи, калории, шаги
- [ ] **OBSV-05**: Карточка наблюдаемого показывает визуальное предупреждение при превышении целевых калорий (`profiles.targets.calories`) или выходе глюкозы за клинический диапазон, с учётом контекста измерения (натощак/после еды)
- [ ] **OBSV-06**: Клик по карточке наблюдаемого открывает детальный вид его данных за сегодня, аналогичный главному экрану владельца данных
- [ ] **OBSV-07**: Пациент может в любой момент отозвать доступ конкретному наблюдателю из списка привязанных в Настройках; наблюдатель может симметрично убрать пациента из своего списка наблюдаемых без участия пациента

## v2 Requirements

Следующий майлстоун — «Релиз в App Store». Не входят в текущий роадмап.

### Авторизация

- **AUTH-01**: Пользователь входит через Apple ID (обязательно для App Store при наличии стороннего входа)
- **AUTH-02**: Пользователь входит через Google
- **AUTH-03**: Пользователь входит по email через OTP-код (`ResendOTP` уже настроен, UI закомментирован)
- **AUTH-04**: Гостевой аккаунт связывается с реальной учётной записью без потери данных
- **AUTH-05**: Данные гостя не теряются при переустановке приложения

### Подписка

- **SUB-01**: Вебхук RevenueCat обновляет статус подписки на сервере без участия клиента
- **SUB-02**: Экран подтверждения после успешной покупки

### Качество

- **QA-01**: Автотесты бизнес-логики Convex (расчёт целей, макросы блюда, недельная выборка)
- **QA-02**: Валидация аргументов во всех Convex-функциях
