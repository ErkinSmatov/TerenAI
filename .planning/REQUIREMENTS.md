# Requirements: TerenAI

**Defined:** 2026-08-05
**Core Value:** Пользователь фотографирует еду и через несколько секунд видит достоверные калории и БЖУ — без ручного ввода и поиска по базе.

**Майлстоун v1.3 — «Стабильный билд в TestFlight»:** приложение запускается, гость пользуется им без регистрации, тестер проходит основной сценарий без блокирующих ошибок.

## v1 Requirements

### Наблюдаемость (OBS)

- [x] **OBS-01**: Краши и необработанные ошибки в релизной сборке попадают во внешний сервис отчётов (не только в `console.error`), с указанием версии сборки и платформы
- [x] **OBS-02**: Существующий хелпер `lib/utils/logError.ts` отправляет ошибки в этот сервис, сохраняя текущее поведение в dev
- [x] **OBS-03**: Стек-трейсы релизной сборки читаемы (загружены sourcemaps для EAS-билда), а не минифицированы
- [x] **OBS-04**: Команда может собрать production-сборку локально и воспроизвести на ней поведение релиза

### Запуск приложения (BOOT)

- [x] **BOOT-01**: Приложение, установленное из TestFlight на iOS, доходит до первого экрана без краша
- [ ] **BOOT-02**: Отсутствие или опечатка в переменной окружения продакшн-среды не приводит к молчаливому крашу при старте — ошибка видна и диагностируема
- [ ] **BOOT-03**: Все нативные модули, от которых зависит код, объявлены в конфиге production-сборки (нет расхождения между установленным пакетом и подключённым плагином)
- [ ] **BOOT-04**: Причина краша 1.2.1 (1) зафиксирована письменно, чтобы регрессия распознавалась повторно

### Гостевой доступ (GUEST)

- [x] **GUEST-01**: Новый пользователь при первом запуске попадает в приложение, не видя экрана авторизации
- [x] **GUEST-02**: Гость проходит онбординг и получает персональные цели по калориям и БЖУ
- [x] **GUEST-03**: Гость создаёт блюдо по фото и видит рассчитанные калории и БЖУ
- [x] **GUEST-04**: Данные гостя (профиль, цели, блюда) сохраняются между запусками приложения
- [x] **GUEST-05**: Пользователь может войти в аккаунт по собственной инициативе из настроек — вход не навязывается
- [x] **GUEST-06**: Лимит AI-запросов применяется к гостю так же, как к зарегистрированному пользователю
- [x] **GUEST-07**: Гостевая сессия не ломает подписку: статус RevenueCat корректно соотносится с гостевым пользователем

### Вход по номеру телефона (AUTH) — добавлено 2026-08-20, реализовано вне GSD-цикла в рамках Phase 3

- [x] **AUTH-06**: Пользователь входит по номеру телефона через Telegram OTP (Telegram Gateway API, `convex/TelegramOTP.ts`)
- [ ] **AUTH-07**: Пользователь входит по номеру телефона через WhatsApp OTP (Twilio Verify, `convex/WhatsAppOTP.ts`) — код реализован, интеграция подтверждённо не работает, требует отладки (см. STATE.md Pending Todos)

### Экспорт отчёта (REPORT) — добавлено 2026-08-20, реализовано вне GSD-цикла

- [x] **REPORT-01**: Пользователь выгружает PDF с месячной сводкой питания/глюкозы из настроек (`app/app/(tabs)/settings.tsx`, `convex/reports/getMonthlyReport.ts`, `lib/reports/buildMonthlyReportHtml.ts`) для передачи врачу

### Сквозной сценарий тестера (FLOW)

- [x] **FLOW-01**: Открытие блюда не падает, если продукт отсутствует в базе — блюдо отображается с деградацией, а не с ошибкой всего экрана
- [x] **FLOW-02**: Ошибка при исправлении блюда через AI показывается пользователю, а не теряется молча
- [x] **FLOW-03**: Экран недельной истории показывает блюда в правильных днях, включая переход на летнее/зимнее время
- [x] **FLOW-04**: Тестер проходит путь «онбординг → фото блюда → калории на главном экране» на TestFlight-сборке без блокирующих ошибок

### Дистрибуция (DIST)

- [ ] **DIST-01**: Существует профиль сборки для тестирования, не смешивающий тестовые билды с релизными кандидатами
- [ ] **DIST-02**: Процесс «собрать и залить в TestFlight» описан и воспроизводим по шагам

### Наблюдатель за пользователем (OBSV)

- [x] **OBSV-01**: Наблюдатель (родитель/ребёнок/врач — одна функциональная роль) подключается к аккаунту пациента через собственный аккаунт (обычный вход/гостевой режим) и постоянный многоразовый код пациента
- [x] **OBSV-02**: Пациент видит и управляет своим кодом в новом разделе Настроек; один пациент может делиться кодом с несколькими наблюдателями одновременно
- [x] **OBSV-03**: Наблюдатель может подключиться к нескольким пациентам сразу (несколько кодов) и видит их всех в едином списке наблюдаемых
- [x] **OBSV-04**: Список наблюдаемых доступен по кнопке в шапке главного экрана (`components/home/HomeHeader.tsx`) и показывает карточку на каждого пациента с сегодняшними данными: глюкоза, количество приёмов пищи, калории, шаги
- [x] **OBSV-05**: Карточка наблюдаемого показывает визуальное предупреждение при превышении целевых калорий (`profiles.targets.calories`) или выходе глюкозы за клинический диапазон, с учётом контекста измерения (натощак/после еды)
- [x] **OBSV-06**: Клик по карточке наблюдаемого открывает детальный вид его данных за сегодня, аналогичный главному экрану владельца данных
- [x] **OBSV-07**: Пациент может в любой момент отозвать доступ конкретному наблюдателю из списка привязанных в Настройках; наблюдатель может симметрично убрать пациента из своего списка наблюдаемых без участия пациента

### Двухэтапное распознавание блюда (MEAL) — добавлено 2026-08-21 (Phase 7 planning prep)

- [x] **MEAL-01**: После отправки фото или текстового описания блюда пользователь в течение нескольких секунд видит список распознанных ингредиентов с граммовкой — до старта поиска кандидатов в базе продуктов и расчёта КБЖУ
- [x] **MEAL-02**: Пользователь может изменить название/граммовку любого ингредиента в этом списке, добавить новый или удалить лишний, прежде чем подтвердить
- [x] **MEAL-03**: После подтверждения списка тяжёлая часть анализа (поиск кандидатов в базе, перевод, health score, расчёт КБЖУ) выполняется асинхронно — пользователь не остаётся на блокирующем экране ожидания
- [x] **MEAL-04**: Когда фоновая обработка завершается, пользователь получает уведомление о том, что блюдо распознано и записано
- [x] **MEAL-05**: Главный экран (дневная сводка калорий/БЖУ) обновляется автоматически без ручного действия пользователя, когда обработка блюда завершается

### Apple Health, оценка глюкозы, месячная история (HEALTH/GLU/HIST) — добавлено 2026-08-25 (Phase 68 planning prep)

- [x] **HEALTH-01**: Данные из Apple Health (движение, глюкоза) синхронизируются надёжно — `useHealthKitSync`/`importHealthKitReadings` фактически обновляют данные в приложении, а не зависают/молча не срабатывают
- [x] **GLU-01**: Приложение показывает приблизительную оценку уровня глюкозы в крови, рассчитанную от содержания сахара (углеводов) в съеденной еде — как дополнение к измеренным показаниям, а не замена
- [x] **HIST-01**: История питания/показателей доступна не только за текущую неделю, но и за произвольный месяц
- [x] **HIST-02**: Нажатие на незаполненный день недели (или аналогичный элемент) открывает экран календаря; нажатие на дату в календаре открывает уже существующий экран аналитики за этот день

### Онбординг, взвешивание, push-напоминания, геймификация (ONBOARD/WEIGH/PUSH/MEALPUSH/BADGE/HEADER) — добавлено 2026-08-30 (Phase 69 planning prep)

- [ ] **ONBOARD-01**: Все нерешённые пункты TODO.md по онбордингу проверены ручным прогоном; невоспроизводящиеся закрыты, воспроизводящиеся исправлены точечно (новый контент в онбординг не добавляется)
- [x] **WEIGH-01**: Через 7 дней после последнего обновления веса приходит push-напоминание взвеситься; напоминание повторяется, пока вес не обновлён
- [x] **WEIGH-02**: Отдельный лёгкий экран «только вес» сохраняет новый вес и автоматически пересчитывает цели по калориям и БЖУ, не разрушая остальные поля профиля
- [x] **PUSH-01**: Общая push-инфраструктура: запрос разрешения, регистрация Expo-токена устройства вместе с часовым поясом, серверная отправка уведомлений, переход на нужный экран по тапу
- [x] **PUSH-02**: Каждый push-канал (взвешивание, приёмы пищи) включается и выключается независимым тумблером в Настройках
- [x] **MEALPUSH-01**: Напоминания записать приём пищи приходят в три фиксированные точки дня по локальному времени пользователя
- [ ] **MEALPUSH-02**: Push для точки дня пропускается, если приём пищи в соответствующем окне уже записан; текст напоминания апеллирует к стрику пользователя
- [x] **BADGE-01**: Бейджи начисляются на сервере идемпотентно при пересечении порогов стрика и количества записанных приёмов пищи
- [ ] **BADGE-02**: Витрина достижений доступна из Настроек и показывает полученные и ещё не полученные бейджи
- [ ] **BADGE-03**: При получении нового бейджа показывается моментальное празднование в приложении, в том числе если бейдж начислен фоновой обработкой блюда
- [ ] **HEADER-01**: Кнопка стрика в шапке главного экрана ведёт на объединённый экран «стрик + календарь» с переходом на аналитику дня; отдельная кнопка календаря удалена, переход к списку наблюдаемых вынесен на отдельную кнопку

## v2 Requirements

Следующий майлстоун — «Релиз в App Store». Не входят в текущий роадмап.

### Авторизация

- **AUTH-01**: Пользователь входит через Apple ID (обязательно для App Store при наличии стороннего входа)
- **AUTH-02**: Пользователь входит через Google
- **AUTH-03**: Пользователь входит по email через OTP-код (`ResendOTP` уже настроен, UI закомментирован)
- **AUTH-04**: Гостевой аккаунт связывается с реальной учётной записью без потери данных
- **AUTH-05**: Данные гостя не теряются при переустановке приложения

### Подписка

- **SUB-01**: Вебхук RevenueCat обновляет статус подписки на сервере без участия клиента
- **SUB-02**: Экран подтверждения после успешной покупки

### Качество

- **QA-01**: Автотесты бизнес-логики Convex (расчёт целей, макросы блюда, недельная выборка)
- **QA-02**: Валидация аргументов во всех Convex-функциях
