# TerenAI

## What This Is

Мобильное приложение (iOS/Android) для учёта питания: пользователь фотографирует блюдо, ИИ распознаёт ингредиенты, оценивает вес и считает калории и БЖУ по базе USDA FoodData Central и Open Food Facts. Русскоязычный интерфейс, монетизация через подписку (RevenueCat). Ранее назывался CalYo, переименован в TerenAI.

Приложение уже написано и функционально, но **не запускается из TestFlight** — краш при старте на iOS (версия 1.2.1 (1)). Текущая работа — довести сборку до состояния, в котором ей можно дать пользоваться тестерам.

## Core Value

Пользователь фотографирует еду и через несколько секунд видит достоверные калории и БЖУ — без ручного ввода и поиска по базе.

## Context

**Состояние кодовой базы** (карта в `.planning/codebase/`):
- Expo SDK 54 / React Native 0.81.5 / React 19 с включённой New Architecture (`newArchEnabled: true`) и React Compiler — свежий и относительно рискованный стек; в TODO.md уже отмечены проблемы с `react-native-reanimated` 4.x производительностью и «Reanimated error on onboarding screen»
- Бэкенд — Convex; клиент почти не содержит бизнес-логики
- `ios/` и `android/` закоммичены (prebuild-workflow, не чистый managed Expo)

**Почему краш непонятен:** в проекте нет Sentry или другого краш-репортинга. `lib/utils/logError.ts` делает только `console.error`, который в релизной сборке не собирается никуда. Диагностику придётся добывать через Xcode Organizer / локальную release-сборку либо сразу подключить краш-репортинг.

**Почему «пропустить экран входа» не работает напрямую:** вся группа роутов `app` обёрнута в `<Stack.Protected guard={isAuthenticated}>` (`app/_layout.tsx:16-18`), и 20 файлов в `convex/` гейтятся через `getAuthUserId`. Отключение экрана входа без реального `userId` оставит пользователя в пустом стеке с падающими запросами.

**Известные баги, отмеченные командой** (`.planning/codebase/CONCERNS.md`, `TODO.md`):
- `getMeal` жёстко бросает ошибку при отсутствующем `food` — падает весь запрос блюда
- `getWeekMeals` некорректен на переходах DST + использует `.filter()` вместо индекса
- `fix-meal.tsx` вызывает `void correctMeal(...)` без `await` — ошибки молча теряются, пользователь всегда уходит с экрана
- Кнопка «Продолжить с Apple» отображается, хотя `usesAppleSignIn: false` и плагин `expo-apple-authentication` закомментирован
- Нет вебхука RevenueCat — статус подписки обновляется только когда клиент сам дёрнет sync

**Рынок:** русскоязычный. `lib/off/fetchProduct.ts` жёстко зашит на `ru` локаль на уровне данных.

## Constraints

- **Tech stack**: Expo SDK 54 + New Architecture + React Compiler — обновлять мажорные версии в рамках стабилизации нельзя, это внесёт новые переменные в отладку краша
- **Auth**: остаёмся на `@convex-dev/auth` до конца майлстоуна — миграция на better-auth переделает всё, что построим для гостевого режима
- **Данные**: гостевой пользователь должен быть настоящим `userId` в Convex, иначе 20 существующих функций и `<Stack.Protected>` придётся переписывать
- **Дистрибуция**: `eas.json` не имеет отдельного preview-профиля — TestFlight-сборки идут через `production` с `autoIncrement: true` и `appVersionSource: "remote"`
- **Наблюдаемость**: пока нет краш-репортинга, любая починка продакшн-бага — это гадание; это ограничение снимается первым
